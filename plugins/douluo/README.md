## 这是什么

Roost 的斗罗大陆文字游戏插件。**目标不是复刻某个现成插件，而是把它有的功能做得更好**——
覆盖同样的玩法面，但在下面这些点上明确不一样：

| 同类插件的问题 | 这里的做法 |
|---|---|
| 95 条顶层指令平铺，菜单要滑两屏 | **28 个词** + 分组菜单，其余靠 `帮助 <域>` 二次展开 |
| ASCII 框线菜单，玩家照着敲 | **markdown + 可点击指令**（`<qqbot-cmd-input>`），点一下填进输入框 |
| 参数空格 / `-` / 数字拼接三种混用 | **一律空格**，参数错就给用法，不静默 |
| 13.5% 的指令完全没回复 | **零静默**：认不出也回一句 + 给候选 |
| 只有「攻击 / 魂技」，回合制退化成比大小 | 加 **防御**（减伤 50% + 回魂力），攒魂力放大招成为策略 |
| 伤害失控（普攻 1169 vs 魂技 192847，差 165 倍） | 三层倍率各自封顶（属性≤2× 威力≤4× 暴击≤2×），怪物血量**按回合数生成** |
| 挂机回来被补算几百次打死 | 补算**上限 5 回合**，超时判逃跑不判死亡 |
| 战斗状态放临时库，重启就丢 | 战斗**落库**，断线能接着打；怪物属性开战即快照 |
| 纯数字看不出进度 | 面板和战斗都带 **▰▱ 血条** |
| 怪物血量按玩家输出反推 → **越练越没感觉** | 怪物由**内容**生成；升级 20 级后同一只怪回合数明显下降（体检可验证） |
| 指令无前缀，群里聊天会误触发 | **可配置前缀**（默认 `/`），面板页里能改，菜单自动跟着变 |
| 图写死在插件里，换图要改代码（实测 453 条回复里只有 4 条带图） | 图是**内容表的 `image` 列**，面板换图即可；三处用图：武魂 / 地图 / 开战 |
| 魂灵/战宠/战魂/集卡 四套表四套逻辑（40+ 条指令） | **一张 `companion` 表 + `kind`**，6 个动词；集卡**收集即生效**不用出战 |
| 7 个商城各写一遍扣钱给货（改一处漏三处） | **一个 `trade()`** 管所有交易，余额判断只有一份 |
| 好友/情侣/师徒/仇人 各一套表（社交 4 套 + 组织 4 套 + 生活 3 套） | **relation / guild / recipe 三张表** 覆盖全部，86 个动词封顶 |

## 伙伴：魂灵 / 战宠 / 战魂 / 集卡

四样东西在同类插件里是四套表、四套逻辑、40 多条指令。它们的共同点只有两个：

- **soul / pet / wsoul**：要**出战**才生效，同类只能上一个
- **card**：**收集即生效**（图鉴加成），不占出战位

所以只有一张 `companion` 表 + `kind`，六个动词：`伙伴` `魂灵` `战宠` `战魂` `集卡` `出战` `收回`。

```
/魂灵          → 只列魂灵，标出谁在出战、星级、提供哪些属性
/伙伴          → 全部 + 集卡图鉴进度（3/10）
/出战 百年魂灵  → 同类只能一个，占了会告诉你占位的是谁
/集卡          → 收集即生效，不用出战
```

**加成怎么算**：出战的伙伴和已收集的卡都进 `mods()`，和装备、套装一起汇总到属性面板的「加成来源」里。
所以玩家能一眼看到「攻击 114 = 基础 8 + 魂骨 50 + 伙伴 56」这类拆解。

> 顺带修了个真 bug：以前发放伙伴不重算属性，集卡的被动要等下一次穿装备才生效，
> 玩家会以为卡没用。现在 `grantCompanion` / `grantEquip` 都会立刻 `recalc()`。

## 经济：一次交易，四个系统

商城购买、拍卖成交、抽奖、CDK 兑换、银行存取 —— 本质都是**一次「付出 A 换到 B」**。
所以只有一个 `trade()`，其余全是它的薄封装：

```js
trade(openid, { pay: {gold, coupon, items}, gain: {gold, coupon, items, equips, companions}, reason })
```

两条硬规则：
1. 所有写操作在**一个事务**里（半途失败不会「扣了钱没给货」）
2. 每一笔货币/物品变动都写 `tx_log`，面板能追到每一分钱

**pay 和 gain 分开记账、不做净额对冲** —— 早期版本把「花 100 又中 100」合成一条 0 变动，
审计时这笔交易直接消失了；现在付出和收入各一条，余额曲线对得上。

| 系统 | 实现 |
|---|---|
| 7 个商城 | `shop` 表 7 行 + `shop_item` 货架，不是 7 套逻辑 |
| 银行 | `bank` 表，按 `bank_interest_hours` 周期结息，存贷各算利率 |
| 拍卖 | `auction` 表；**上架即扣物品**（防一物多卖），过期/下架自动退回 |
| 抽奖 | `lottery_prize` 带权重；先抽完再一次性发奖（避免只发一半） |
| 月卡 | `monthly_card`，购买/每日领取/到期判断 |
| CDK | `cdk` 表 + 面板「经济」页生成，玩家 `/兑换` |

面板新增「经济」页：货币总量 / 存贷 / 在售拍卖 / 奖池，以及**兑换码生成器**。

## 社交 / PVP / 宗门 / 生活

四块也是归并出来的：

| 表面 | 本质 | 实现 |
|---|---|---|
| 好友 / 情侣 / 师徒 / 仇人 | 两个玩家之间的一条关系 | 一张 `relation` 表 + `kind` |
| 斗魂 / PK / 排位 | 异步打一场 | 一个 `duelResolve()` + `duel` 表 + `player.rank_score` |
| 势力 / 帝国 / 宗门 / 家族 | 一个玩家团体 + 成员身份 | `guild` + `guild_member` |
| 炼丹 / 合成 / 设计图 / 打造 | 配方 + 材料 → 产物 | 一张 `recipe` 表 + 一个 `craft()` |

**PVP 不靠比战力**：`duelResolve()` 按回合真打，速度决定先手，每一下伤害都记在 `duel.log` 里。
比战力的问题是「我战力高为什么输」没法解释；真打能复盘，而且和 PVE 共用同一套伤害公式。

**关系要双方确认**：发起是 `pending`，对方 `答应` 才变 `active`。避免被单方面绑情侣。

**领地配置和归属分开放**：`content.territory_def` 存「这地图能产什么」，
`game.territory` 存「现在归谁」。业务代码不写内容库，这条边界一直守着。

**挖矿按小时结算、最多累计 12 小时**：不按时收不会无限攒，防挂机。

## 内容：从旧版 INI 迁移

`scripts/import-ini.mjs` 把旧版（CAQ 斗罗大陆）的 53 个 INI 转成 `src/db/content-pack.sql`。

**只参考三样，数值全部重算**：

| 取什么 | 为什么 |
|---|---|
| **名字** | 原著向的魂兽/地图/NPC/物品/武魂 |
| **关系** | 哪只怪在哪张图、哪张图连哪张图、NPC 在哪 |
| **年龄/描述** | 魂兽年龄决定魂环年限，是原著设定 |

数值（生命/攻/防/目标回合）由 `engine/balance.js` 按年龄现算，所以导入后
`GET /balance/check` 仍然全绿。**旧版数值是另一套公式，直接搬会把平衡打崩**
（史莱姆 age=50 就有 466 血）。

```bash
node plugins/douluo/scripts/import-ini.mjs            # 重新生成
node plugins/douluo/scripts/import-ini.mjs --dry      # 只看统计
```

导入结果：**42 张地图 / 50 只魂兽 / 23 个 NPC / 152 件物品 / 39 个武魂 / 33 个任务**。

三个处理上的坑（都踩过）：

1. **年龄要按排名压缩**。旧版 45 只怪年龄中位数是 7 万，硬分档会得到 32 个 BOSS，
   开局没怪可打。现在只保留相对强弱，把年龄铺到 十年→百年→千年→万年→十万年 六个档。
2. **关联要按名字回查 id**，不能写死 id。同名地图（圣魂村）已经在手写种子里，
   写死 id 会撞外键。
3. **武魂要缩放到本插件量级**。旧版攻击 20–60，我们是 8–14；直接搬会让「标准武魂」
   中位数翻四倍，怪物跟着变强，新号被十年白虎打死。

## 通关测试

```bash
node plugins/douluo/test/playthrough.mjs
```

用一个「自动玩家」从建号开始真玩：找怪 → 挑战 → 攻击到死 → 附加魂环 → 换图 → 休息。
断言的是**会不会卡死**，不是几回合：

- 前 10 场胜率 ≥ 80%（开局不能被劝退）
- 30 场后等级 > 1 且有魂环（有成长）
- 从起点可达 ≥ 8 张图（世界不封闭）
- 胜率不崩、等级不被魂环卡死
- 最后再跑一次体检，确认内容没把平衡搞坏

这一跑抓出了三个真问题：**没回血手段**（连打 4 场必死）、**死亡后没钱复活**（死锁）、
**43 杀攒满 10 环**（魂环墙被玩穿）。对应改了三处：加 `休息` + 被动回血、
复活默认免费半血、魂环加年限门槛。

## 系统深化：给每个系统一个「非它不可」的理由

功能面齐了之后，真正的问题是**有些系统开了等于没开**：战舰只是个开关，
宗门等级永远不动，情侣只是条记录。参考现代游戏的做法逐个补上：

| 系统 | 之前 | 现在 |
|---|---|---|
| **魂骨/装备** | 只能穿脱 | `强化 <名>` 必成 + 成本按 `lv^1.6` 递增，10 级封顶 |
| **宗门** | 等级是装饰字段 | `宗门升级` 花资金 → **全员全属性 +2%/级**（乘区） |
| **情侣** | 只是条记录 | 双方**同时在线**打怪经验 +15%（一方离线就没有） |
| **师徒** | 只是条记录 | 徒弟涨经验，师父分 5% |
| **战舰** | 开了什么也没发生 | 激活后 `移动` 可**越过地图等级门槛** |

三个设计取向值得记：

1. **强化用「必成」不用随机成功率**。随机强化是手游最典型的挫败来源
   （连败十次直接退游），而文游玩家没有氪金补救通道，只能骂人。
2. **宗门加成走「乘区」不走「加法」**。加法会被装备固定值放大、随内容量漂移；
   乘区只放大「基础+固定」这一整块，可控。闪避/暴击不吃乘区（否则后期必满）。
3. **关系收益必须带条件**。情侣加成要求双方 5 分钟内都动过，
   否则就成了「挂个情侣位白嫖经验」。

## 系统联动：让各系统互相「用得上」

功能齐了之后最容易犯的错是**每个系统自己玩自己的**。判断标准很简单：
如果删掉某个系统，玩家会明显觉得少了东西吗？按这个标准补了五处：

| 原来 | 现在 |
|---|---|
| 伙伴只加属性，战斗中不出现 | **每回合 30% 概率追击**，战斗日志里能看到「火狐 追击 23」 |
| 多余装备只能压箱底 | `分解 <装备>` 换魂环碎片，喂给炼丹/合成 |
| NPC 是死数据（只有一行 dialog） | `对话 <NPC>` 显示对话 + 他能给的任务 + 当前状态 |
| 任务条件只有 kill/level | 补上**收集物品**（导入的任务里有，之前永远交不了） |
| 玩家不知道下一步该干嘛 | `属性`/`菜单` 顶部给**一条动态建议** |

最后一条最值钱。文游最大的流失点不是「没内容」，是**89 个指令摆在那，新玩家只会重复发「攻击」**。
`nextHint()` 按状态给一条最该做的事，不罗列菜单：

```
阵亡 → 复活        有魂环没附 → 附加魂环     血低于 40% → 休息
有能交的任务 → 完成任务 X                  卡在魂环墙 → 打环
背包有药且血不满 → 使用 X                  什么都没接 → 对话 NPC
```

### 还能做但没做的（按性价比排）

1. **邮件系统** —— 奖励直接进背包，玩家下线时被发奖不会知道；也缺一个补偿渠道
2. **自动战斗 `自动`** —— 一场 4 回合 4 条消息，群里刷屏；`resolveRound` 是纯函数，循环即可
3. **每日任务** —— 现在任务只有主线，没有每日刷新
4. **赛季重置** —— 排位分只涨不清，长期会板结
5. **成就/图鉴** —— 收集感是长线动力，但要内容量够才有意义

## 邮件 + 自动战斗（补体验的两块短板）

**邮件**：解决「玩家不在场时发生的收益，他不知道自己拿到了」。
拍卖成交、运营补发走邮件，上线能看到「你有 N 封未领」、能追查、能过期。
附件统一过 `EconomyRepo.trade()`，所以流水和钱包永远一致。

```
/邮件           → 列表（标未领，显示附件摘要）
/领取 3         → 领一封
/领取 全部      → 一键领完
```

**自动战斗**：一场 4 回合就是 4 条消息、4 次操作，群里三个人同时打怪能刷出十几条。

```
/自动           → 打完当前这场，结果合并成一条
/自动 3         → 连打 3 场（自动接下一只同名怪）
```

它**不替玩家做决策**（不用魂技、不吃药），只重复普攻——想手动的人继续用 `攻击`，两者共存。
`autoFight()` 复用 `act()`，所以和手动打的结果完全一致。

## v10：一次加了十几套系统，只新建 8 张表

对齐三个参考斗罗（麒麟 389 个指令词 / CAQ 52 个 INI）后，除了「不建议做」的全部补上。
**靠的还是归并**——十几个系统只用 8 张内容表：

| 表面 | 本质 | 实现 |
|---|---|---|

| 万兽台 / 深渊 / 世界BOSS / 神位 | 有层数、有每日次数、有奖励的 PVE | **一张 `challenge`** + kind |

指令 **94 → 124**，内容表 **23 → 31**。

几个设计决定：

- **战力落库**：它是算出来的，但排行榜要按它排序，SQL 排不了 JS 函数，所以 `recalc()` 顺手写一份。
- **功法走 `extras` 通道**：不吃装备等级系数、不被宗门乘区放大两次。

- **称号自动授予**：之前只有 4 条死数据、没有任何获取途径。

**明确没做**：仓库（背包无上限，加了是退步）、贵族/氪金（支付资质 + 禁收费底线）、
PK 强杀（劝退新人）、星际穿越（需要跨服，做了是假功能）、宗门战（单机测不出对抗性）。

## v11：宗门战 / 领地争夺 + 丹药四件套

### 宗门战与领地争夺

之前跳过是因为「需要多宗门并存才有对抗性」。现在用折中方案让它单服可玩：

```
宣战（花 2000 资金，24 小时有效）
  → 抢夺 <地图>（打守卫）
    → 赢：领地易主，新守卫强度按你的宗门等级算
    → 输：对方守住，宗门资金 +300，守卫强度 +10（下次更难抢）
```

**守卫强度由「占领方宗门等级 + 占领时长」决定**，所以即使对方不在线，
也能体现「他的宗门有多强」。守卫用 `monsterStats` 现算，和普通魂兽同一套数值，
不会出现「领地守卫比同级魂兽强十倍」这种失控。

三个设计决定：

1. **必须先宣战**。直接抢等于强者无成本碾压，小宗门连反应机会都没有；
   宣战要花钱、有 24 小时窗口，守方有时间升级宗门、加固守卫。
2. **占领和抢夺分开**。无主地 `占领` 就行；有主的必须先 `宣战` 再 `抢夺`，
   直接 `占领` 会被拦下并提示正确路径。
3. **收工有每日次数上限**。早期 `挖矿` 没上限，一个人能把宗门产出全收走；
   现在按宗门等级加成 + 每天 3 次，宗门升级才有实际回报。

### 丹药四件套（鼎 / 火 / 药材 / 品质）

之前只有 `recipe` 一张表，把「丹鼎/丹方/药材/丹火/丹药」五件套归并掉了。
归并本身是对的（一张表覆盖炼丹/合成/设计图），但**丢了炼丹的手艺感**。现在补回来：

| 组件 | 作用 |
|---|---|
| **药材** | 蓝银草/鸡冠凤凰葵/八角玄冰草/相思断肠红/龙芝叶（`item.kind='herb'`） |
| **丹鼎** | 青石鼎 +5% / 玄铁鼎 +12% / 九龙鼎 +20% |
| **丹火** | 兽火 +5% / 地心火 +12% / 幽冥火 +20% |
| **品质** | 成功后 roll：下品 ×1 / 中品 ×2 / 上品 ×3 |

```bash
/丹鼎 九龙鼎      # 换鼎
/丹火 幽冥火      # 换火
/炼丹 回魂丹·真 5  # 炼 5 次，出成功率/品质/产出
```

**`制作` 和 `炼丹` 是两套**：`制作` 必成（材料换产物，合成/设计图走这个），
`炼丹` 有成功率和品质——因为炼丹靠鼎和火，这才有「手艺」可言。

失败只扣一半材料（不做全损，那是老式页游的劝退设计）。

**踩到的数值坑**：20 级炼 1 级丹方时，等级加成给了 +38%，直接把丹鼎丹火的价值压没了——
玩家没理由买鼎买火，四件套退化成一件。现在等级加成**封顶 +20%**。

### 数值不能直接搬

原版的数值量级是**亿级**（魂兽生命中位数 5 亿、魂技威力中位数 8000），
我们是**百级**。直接搬会让整个数值体系崩掉。

导入器 `scripts/import-console-ini.mjs` 做两件事：
1. **搬结构**：名字、字段关系、稀有度、等级需求、百分比类属性 → 原样导入
2. **标定数值**：绝对值属性按分位数用**幂函数**映射到我们的曲线

用幂函数而不是线性，因为原版数值是「指数膨胀」的（越后期越离谱），
线性映射会把前 90% 的内容压成一个点。

### 这一版踩的坑（都是同一类）

**坑一：`UPDATE` 子查询不能引用外层表名**

```sql
-- 报 no such column: map.min_level
UPDATE map SET north = (SELECT id FROM map WHERE ... map.min_level ...);
-- UPDATE ... FROM 也一样报
```

SQLite 就是这么限制的。地图连通、空地图配怪这两件事最后都用**纯 JS BFS** 做了。

**坑二：`CREATE UNIQUE INDEX` 在已有重复数据时会失败**

`uq_drop` 是后加的唯一索引，老库里同一只怪已经攒了 417 组重复配置
（`INSERT OR IGNORE` 在没有唯一约束时等于普通 INSERT）。
直接建索引会报 `UNIQUE constraint failed`，而 `content.sql` 是**整段 exec** 的——
一条失败会让整个插件加载失败，不是「跳过一条语句」那么轻。
现在建索引前先 `DELETE ... WHERE rowid NOT IN (SELECT MIN(rowid) ... GROUP BY ...)`。

**坑三：`cat >> file <<'EOF'` 写不进去**

中文和反引号会让 heredoc 提前结束，命令"看起来成功"（`echo ok` 照样打印），
但文件根本没写入。这一版因此丢了 `post2.sql`、`console-pack.sql`、v24 的建表语句，
以及 `open.js` 的后半段——**全都是用 heredoc 写的**。
现在一律用 Write 工具或 JS 的 `fs.writeFileSync`。

**坑四：`INSERT OR IGNORE` 不会更新老行**

改了导入逻辑重跑，老库里已存在的行会被跳过，`effect` 一直是旧值。
试过 upsert（`ON CONFLICT(id) DO UPDATE`），但 id 是「按 ini 顺序生成的序号」，
重新生成时 id↔name 映射会漂移，更新 name 必然撞 UNIQUE。
最后用「`INSERT OR IGNORE` + 按 id 的 `UPDATE` 修正段」解决。

## v25：NPC 条件对话 + 菜单全覆盖

### 条件对话：同一句台词说两遍是设计缺陷

原版 ini 里 NPC 只有「平常对话」一个纯文本字段，条件分支是运行时按前缀拼的，
**没有可导的结构**。所以这块是自己设计的。

**条件格式**（全在 `npc_dialog.cond` 的 JSON 里，语义是全部 AND）：

```json
{ "level": 20 }              // 最低等级
{ "levelMax": 40 }           // 最高等级
{ "ring": 3 }                // 最低魂环数
{ "gold": 10000 }            // 最低魂币
{ "kill": 100 }              // 最少累计击杀
{ "item": { "name": "玄铁", "qty": 5 } }
{ "time": "night" }          // day / night（按服务器小时）
```

**动作**：

| 写法 | 效果 |
|---|---|
| `''` | 只是说话 |
| `heal` | 回满血和魂力 |
| `give:<物品名>*<数量>` | 给东西，**只给一次**（靠 `player_meta` 记 `dlg:<npc_id>:<sort>`） |

加新条件维度只要在 `dialogCondOk()` 里加一个 `if`，不用改表结构。

**为什么按「身份」套模板**：50 个 NPC 手写 200 段对话不现实，
玩家也记不住第 37 个村民说过什么。按身份分 7 类（孟婆/村长/长者/商人/向导/唐昊/兜底），
每类 2–5 段，保证「同一个人在不同阶段说的话不一样」——这才是条件对话的价值。

**用 SQL 的 LIKE 匹配，不是读 ini 名字列表**：

```sql
INSERT OR IGNORE INTO npc_dialog (npc_id, cond, text, action, sort, enabled)
  SELECT id, '{...}', '...', '', 0, 1 FROM npc WHERE name LIKE '%长老%' OR name LIKE '%将军%';
```

原因：`村长` 是我们自己在 content-pack 里加的，原版 NPC列表.ini 里没有；
反过来原版有些 NPC 我们又没导。按名字列表生成必然漏。
用 LIKE 直接对数据库里的 npc 表匹配，覆盖所有现有和以后新增的 NPC。

一个 NPC 可能同时命中多个类别，同一 `sort` 撞 `uq_npcdlg(npc_id, sort)` 时
`INSERT OR IGNORE` 会跳过，所以 **ARCH 的顺序就是优先级**——
特殊 NPC（孟婆/村长/唐昊）必须排在通用类别前面。

结果：**196 段，覆盖 50/50 NPC**。

真机效果：

## 依赖的框架能力

这个插件用到了一个**新增的框架能力**（本机已打补丁）：

| 能力 | 位置 | 作用 |
|---|---|---|
| `ctx.registerRoute(method, path, handler)` | `src/plugin/routes.js`（新增）<br>`src/plugin/context.js`（+ 方法）<br>`src/plugin/loader.js`（+ 注册表接线）<br>`src/web/server.js`（+ 分发） | 让插件的面板页面能读写自己的数据 |

**为什么要它**：`ctx.registerPage()` 只是把一段静态 HTML 塞进 iframe，服务端不会在每个请求时回调插件。
所以页面能画出来，却拿不到 SQL 查询结果——只有 `/api/plugins/:id/data` 那个 KV 单键接口，
没有事务、没有查询、没有分页。要「在面板里管理 SQL 数据」，必须有一个真正的数据通道。

接口挂在 `/api/plugins/<id>/r/...`，**鉴权、CSRF、同源校验全部复用面板那一套**，
插件拿不到裸 req/res。老框架没有这个方法时插件会自动跳过（页面只读）。

## v21：图片补齐 + 配置备份

### 图片：273 张，100% 覆盖

之前 `image` 列全空——内容包只带文字，没带美术资源，所以真机发出来的全是纯文本。

现在 `scripts/fill-images.mjs` 支持三种补图方式：

```bash
node scripts/fill-images.mjs --bot main --dry     # 看覆盖率
node scripts/fill-images.mjs --bot main --fetch   # 生成并下载到本地
node scripts/fill-images.mjs --src D:/art         # 用现成美术资源
```

**推荐 `--fetch`**：把图**下载成本地文件**，而不是写远程 URL。
本地文件让 QQ 上传的是文件本身，不依赖第三方服务长期在线，也不受对方限流影响。

| NPC | 暖褐 | 35 |

共 **273 张 · 2.7MB · 平均 10KB/张**。

图库同时放在两处：
- `data/bots/<id>/plugins/douluo/images/`（机器人自己的，优先）
- `plugins/douluo/images/`（随插件分发，**装了就有图**）

`media.js` 先查前者，找不到回落到后者。运营补的真美术放前者会覆盖占位图。

真机验证：`/武魂` `/地图` `/挑战魂兽` 都发出图文同条，QQ 返回了 `multimedia.nt.qq.com.cn` 的图片 URL。

### 配置备份（重要）

联调期间发现一个**上线级隐患**：面板「删除机器人」默认 `purge: true`，
会连配置、数据、日志一起删。而 `config/bots/` 在 `.gitignore` 里（含 AppSecret，绝不能进仓库），
**一旦误删，AppSecret 无处可恢复**，只能去 QQ 开放平台重新拿。

两道防线：

1. **启动时快照**：每次启动把 `config/bots/*.json` 复制到 `config/backups/<时间戳>/`，保留最近 20 份
2. **删除前备份**：`onBotRemove` 第一件事就是把该机器人配置备份一份，**不管 purge 与否**

成本几乎为零，但能救回「误点一次」。

```
/武魂觉醒        → 【武魂觉醒】香肠（史诗）· 图文同条
```

### 删号

```
/删号        → 确认提示（角色名/等级/魂环数 + 后果）
/删号 确认   → 清空所有关联数据
```

**不加任何游戏性限制**（不要求等级、不要求删号道具），

- `text` 给 `属性` 用（带可点链接）

## v23：修「回复里露出 mqqapi:// 长串」

### 问题

群里部分回复直接显示了：

```
(mqqapi://aio/inlinecmd?command=%2F%E9%AD%82%E5%85%BD&enter=false&reply=false)
```

### 根因

`clink()` 生成的是 **markdown 链接**，只有 markdown 消息才会被渲染成可点按钮。
而 `msg.reply()` 和 `media.send({ text })` 发的是**纯文本**——里面的 `[文字](url)` 会原样露出。

踩坑的 3 处：

| 位置 | 场景 |
| --- | --- |
| `武魂觉醒` 没角色 | 「先 [创建账号](…)」 |
| `武魂觉醒` 钱不够 | 「去打怪攒钱：[魂兽](…)」 |
| `删号` 确认提示 | 「确定要删就点 [删号 确认](…)」 |

前两处改成纯文本指令名，第三处改成 `replyMarkdown`（内容本来就是 markdown）。

### 防止再犯

新增 `scripts/lint-links.mjs`：按**括号配对**找出每个 `msg.reply()` / `media.send()` 的参数范围，
检查里面有没有 `clink(`。

为什么按括号配对而不是按行扫：后面的语句里有 clink 也会被算进来，误报率高。

```bash
node scripts/lint-links.mjs
# 检查 419 处纯文本出口（msg.reply / media.send）
# ✓ 纯文本消息里没有 markdown 链接
```

已接进 `test/journey.mjs` 第 13 段，改代码时自动拦。

### 经验

**QQ 的三种出口，能力不一样**：

| 出口 | 渲染 | 能用 clink |
| --- | --- | --- |
| `replyMarkdown({ content })` | markdown | ✓ |
| `replyMenu(title, groups)` | 框架生成链接 | ✓（item.text 用纯文字） |
| `reply(text)` / `media.send({ text })` | 纯文本 | ✗ |
