# 识图与看视频（media-vision）

让机器人真的「看见」图片和视频。

群友发图、发视频，只要叫了机器人（@ 它，或者私聊），插件会在**消息交给 ai-chat 之前**
把媒体换成模型能读的东西：

- **图片**：正常的图原样放行（ai-chat 自己会下载）。只有「太大」或「格式怪」的图才会被
  自己下载下来、缩到 1280 宽、重新压成 JPEG 再交出去 —— 因为 ai-chat 那边单图上限 2MB，
  超了就直接跳过，等于没看见。
- **视频**：本机没有视频理解能力，所以抽帧。按时间均匀取 5%～95% 之间的几帧
  （不取开头黑场和结尾 logo），每帧缩到 768 宽，当成「图片」塞回消息里给下游看。
  正文里会补一句「这是截帧，帧与帧之间的过程看不到」，免得模型以为自己在看连续画面。

## 为什么抽帧要自己起一个 HTTP 服务

模型只能拿到 **URL**（ai-chat 把附件地址写进提示词，再自己 fetch 成 base64）。
所以帧必须有地址。三条路都试过，只有第三条能用：

1. `data:` URL —— 会把整段 base64 塞进提示词，一条视频几 MB，直接把上下文撑爆。
2. 插件自带的 `/api/plugins/media-vision/r/xxx` 路由 —— 只支持返回 JSON，而且在登录鉴权
   和 CSRF 之后，模型那边拿不到。
3. **本插件自己起一个只监听 127.0.0.1 的小服务**：随机端口、路径里带 40 位随机 token、
   只允许 GET/HEAD、每个文件最多被取 12 次、到期自动清。模型在同一台机器上，直接就能取。

## 用法

| 场景 | 怎么用 |
| --- | --- |
| 看图 | 群里 @机器人 发图，或私聊直接发 |
| 看视频 | 群里 @机器人 发视频（或视频文件） |
| 看得更细 | `/识图 深看` 之后 2 分钟内发的那条，会抽 8 帧 |
| 看状态 | `/识图` |
| 改帧数 | `/识图 帧数 6` |
| 临时关掉 | `/识图 关` / `/识图 开` |

`/识图 清` 会清掉图片服务的缓存、重新探测 ffmpeg、删掉临时目录（需要管理员）。

## 装了什么

```
plugins/media-vision/
├── index.js        中间件、命令、面板
├── media.js        ffmpeg/ffprobe 探测、抽帧、下载、压图
├── server.js       本机图片服务
└── README.md       本文件
```

依赖：**只需要 ffmpeg**（同目录有 ffprobe 更好，没有也能跑）。

### 装 ffmpeg

插件按这个顺序自己找，找到了就不用管它：

1. 面板里填的路径
2. `PATH` 里的 `ffmpeg` / `ffmpeg.exe`
3. 环境变量 `FFMPEG_PATH`
4. 常见位置：`C:/D:/E:/ffmpeg/bin`、`C:/Program Files/ffmpeg/bin`、
   Chocolatey（`C:/ProgramData/chocolatey/bin`）、Scoop（`~/scoop/shims`）、
   WinGet（`%LOCALAPPDATA%/Microsoft/WinGet/Links`），以及 macOS/Linux 的
   `/usr/bin`、`/opt/homebrew/bin`

**Windows 最省事**：去 gyan.dev 下 full 版（`ffmpeg-release-full.7z` 或
`ffmpeg-master-latest-win64-gpl`），解压，把里面的 `bin` 文件夹路径（例如
`D:	oolsfmpegin`）粘进面板那栏 —— 不用安装、不用配环境变量、不用管理员权限。

想「开箱即用」给别人：把 `ffmpeg.exe` 和 `ffprobe.exe` 放进 `C:/ffmpeg/bin/`，
插件启动时会自动认，对方什么都不用填。

## 面板设置

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| 启用 | 开 | 关掉后媒体原样交给下游 |
| 抽帧数 | 4 | 一条视频抽几张（1–12） |
| 深看帧数 | 8 | `/识图 深看` 期间用这个数 |
| 帧宽度 | 768 | 每帧缩到多宽（越小越快、越省上下文） |
| 帧质量 | 4 | ffmpeg `-q:v`，数字越小越清晰（2–31） |
| 压图阈值KB | 1800 | 超过这个大小才重整图片 |
| 图片大小上限MB | 20 | 超过直接放弃，连下都不下 |
| 压图宽度 | 1280 | 重整后的宽度 |
| 一条消息最多几张图 | 4 | 和 ai-chat 的「最多看图」保持一致 |
| 视频大小上限MB | 40 | QQ 视频一般 10MB 以内 |
| 超时秒 | 30 | 下载/抽帧单步超时 |
| 临时图保留分钟 | 10 | 帧文件留多久（模型取完就没用了） |
| ffmpeg 路径 | 空 | 一般留空自动找；实在找不到才填 `bin` 目录或 exe 完整路径 |
| 附加说明 | 空 | 想追加到正文里的固定提示 |

## 和别的插件怎么配合

- 它挂在**消息中间件**里（`ctx.use`），比所有插件先跑，改完的附件对下游全部可见。
- **没叫机器人的消息不碰**：群里随便发的视频不会被抽帧、不会占 CPU。
- 和 `reply-judge`（接话判断）不冲突：那边管「这句要不要接」，这边管「接的时候能不能看见」。
- 和 `pixiv-pid` 不冲突：那个是自己发图，这个是看别人发的。

## 安装

**从插件市场装**：面板 →「插件市场」→ 搜「识图与看视频」→ 安装 → 启用。

**手动装**：把整个 `media-vision` 文件夹放进 `roost/plugins/` 下面（路径长这样：
`.../roost/plugins/media-vision/index.js`），面板 → 插件 → 右上角刷新。

两种方式都不用改配置文件，第一次启动会自动写默认值。本插件**没有任何 npm 依赖**，不用 `npm i`。

装完记得装 ffmpeg（见上面「装 ffmpeg」），`/识图` 一看就知道认没认到。想省掉这一步：
把 `ffmpeg.exe`、`ffprobe.exe` 放到 `C:/ffmpeg/bin/`。

## 已知边界

- 只抽画面，**不说话**（不做 ASR）。要听声音得再上语音识别。
- 时长未知的文件（部分容器缺元数据）会按 1s/3s/5s… 取帧。
- 8 帧的「深看」能不能真的全部送到模型，取决于 ai-chat 的「最多看图」——
  那边是 4 的话，插件这边给 8 也会被截到 4。
- 图片重整会损失一点质量（JPEG q=3 + 1280 宽），换来的是「本来会被跳过的大图现在能看见」。
