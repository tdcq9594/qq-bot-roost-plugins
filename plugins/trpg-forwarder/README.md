# 跑团转发器（trpg-forwarder）

把 QQ 群消息桥给**本机的 DSH 侧插件 `dsh-trpg`**，再把它的骰子、守密人叙事实时发回群里。

> ⚠️ **本插件只是「桥」，单独启用不会有任何回复。**
> 骰点、血量、SAN、线索、角色卡、回合回滚全在 `dsh-trpg` 里。
> 装一个没反应，通常就是只装了这一半。

---

## 它为什么存在

跑团需要两件互相打架的事：

1. **群消息要能进到 DSH 侧的跑团引擎**（那边有 SQLite、骰子、模组、AI 守密人）；
2. **回话要走 Roost 的发送链**（同一个 `msg_id` 的 `msg_seq` 递增、被动窗口过期降级、主动消息额度）。

两个进程各管一套序号，腾讯会直接拒发。所以让 Roost 侧保持极薄，只负责搬运。

---

## 它做的两件事

| 方向 | 干什么 |
|---|---|
| 上行 | 中间件接住群消息 → 先写 Outbox（`ctx.storage`）→ 投递给 `dsh-trpg`（默认 `http://127.0.0.1:17322/trpg/event`），失败指数退避重试 |
| 下行 | 暴露 `POST /api/plugins/trpg-forwarder/r/send`，`dsh-trpg` 用它把骰点与剧情发进群，复用 Roost 的 `replyNow` / `sendGroup` 与幂等键 |

命令类消息也走中间件——内核把 `/` 开头的消息当命令处理，没注册过就直接回「没有这个命令」，**不会走到监听器**。中间件在分发之前跑，接住后不调 `next()`，内核就当这条没发生。

## 配置

| 项 | 默认 | 说明 |
|---|---|---|
| `enabled` | 开 | 总开关 |
| `dshUrl` | `http://127.0.0.1:17322` | `dsh-trpg` 监听地址 |
| `token` | 空 | 共享令牌，**必须自己填**，且与 `dsh-trpg` 的 `config.json` 一致。留空时上下行都拒绝（不预置弱口令） |
| `botId` | `main` | 多机器人时区分群会话属于哪只 |
| `timeoutMs` | `3000` | 单次投递超时 |
| `maxAttempts` | `6` | 投递最多重试次数，超了丢事件并告警 |
| `logReply` | 开 | 每次直发写一条 debug 日志 |
| `probeState` | 关 | 是否向 `dsh-trpg` 查询群状态。旧版 `dsh-trpg` 在 `/trpg/state` 上会崩宿主，所以默认关闭，靠 `/trpg start\|pause` 的本地名单兜底 |

---

## 消息怎么分流

- **开团中的群**：所有非命令发言都归守密人（不用每条 @）；命令只接 TRPG 那套。
- **没开团的群**：只接 TRPG 专属命令（`/trpg` `/st` `/ra` `/go` `/luck` `/tactic` `/afk` `/undo` `/note` `/sc` `/jrrp`）。
  `/help` `/status` `/roll` `/r` `/?` 这类**通用命令一律放行**，不跟别的插件抢。
- 机器人自己发的消息、非群消息、空文本：直接放行。

`dsh-trpg` 不可达时，命令进 Outbox 等重试，并回一句说清「缺的是 DSH 侧插件」，而不是让人以为网络抖了。

## 排查

```bash
# 另一半在不在
curl -H "x-trpg-token: 你的令牌" http://127.0.0.1:17322/trpg/health
```

| 现象 | 原因 |
|---|---|
| 发什么都没人回 | 只装了本插件，没装 `dsh-trpg` |
| 插件日志「令牌为空」 | 面板里没填共享令牌 |
| 直发 403 `bad_token` | 两边令牌不一致 |
| 直发失败 `seq_exhausted` | 同一个 `msg_id` 的回复次数用完了，应换个 `msgId`（`dsh-trpg` 侧有池子） |
