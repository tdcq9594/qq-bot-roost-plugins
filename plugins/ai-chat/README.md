# AI 对话

把大模型接进 QQ。**不需要任何指令**——它就在群里待着，自己判断该不该接话。

> v3 从头重写。跟 1.x 的区别：1.x 要 `@机器人 /ai 问题`，3.x 直接说话就行。
>
> 当前版本 **4.3.1**：4.2.0 加了撤回、互动全类型、文本链、情绪闸门；4.3.0 加了私聊流式；
> 4.3.1 修了「被 @ 时模型输出的 `<skip>` 会原样发到群里」和 `<<retract>>` 触发报错两个 bug。

---

## 它怎么工作

```
群里每条消息
   ↓
① 规则门（不花钱）        冷却 / 每分钟配额 / 忽略词 / 别的插件的指令 → 挡掉大部分
   ↓
② 模型判断（一次调用）    不该接就输出 <skip>，一声不吭
   ↓
③ 说话                    该接才接，切段、引用、markdown 都处理好
```

**为什么不会吵**：三层都在起作用。默认回过一次会安静 20 秒，每分钟最多主动接 3 条；
被 @ 时不受这两个限制（那是在叫你）。

**为什么有不想说话的时候**（4.2.0）：情绪低潮时（DSH 报的社交意愿低于 0.3）只接明确叫它的，
被 @ / 被点名不受影响——那是明确在叫它。这个判断 60 秒才问一次 DSH，
因为情绪本来就是慢变量（半衰期 4 小时），60 秒的陈旧完全可以接受。
问不到 DSH 就当正常，**别让它因为拿不到数据就不说话**。

**别的插件的指令为什么不用管**：内核在分派阶段就把 `/xxx` 交给对应插件并 `return` 了，
插件监听器根本收不到。这是框架保证的，不是我们算的。

## 快速开始

### 1. 打开「接收所有消息」

机器人要能看见群里**所有**消息（不只是 @ 它的），得在
[QQ 开放平台](https://q.qq.com) → 你的机器人 → 开发设置里打开「**接收所有消息**」。
不开的话只有 @ 它的消息能进来，`AI 自己判断` 就退化成「只在被 @ 时说话」了。

### 2. 装 dsh-roost

这个插件**不直连模型**，它只做「QQ ↔ DSH」的桥：把群里的消息交给 DSH，
再把 DSH 的回话发回群里。模型、Key、参数全在 DSH 那边配。

装 [dsh-roost](https://github.com/tdcq9594/dsh-roost) 就行，
默认地址 `http://127.0.0.1:17321`，一般不用改。

> 4.0.0 之前这里还要填 `API 密钥` / `接口地址` / `模型`，
> 那套已经删了——同样的能力 DSH 本来就有，留两份只会两边配置打架。

### 3. 在群里说话

```
今天好热啊
```

不用 @，不用 `/ai`。它觉得该接就接，不该接就看着。

## 配置

### 什么时候接话

| 字段 | 默认 | 说明 |
|---|---|---|
| `什么时候接话` | AI 自己判断 | 另一个选项是「只在被 @ 时说话」，最省 token |
| `接话冷却（秒）` | 20 | 回过一次后安静这么久 |
| `每分钟最多接几条` | 3 | 0 = 不限。被 @ 时不受限制 |
| `忽略这些开头` | `["/"]` | 第二道保险，防别的插件把前缀改了 |

### 人设

| 字段 | 说明 |
|---|---|
| `人设` | 全局系统提示词 |
| `群聊追加人设` / `私聊追加人设` | 按场景叠加 |

**按群单独设人设**：不用改配置——直接跟它说「以后在这个群里你是个毒舌群友」，
它会自己记下来（见下）。

### 记忆

**也没有指令。** 直接说：

| 你说 | 它做 |
|---|---|
| 「记住我住在杭州」 | 这个会话以后都记得 |
| 「忘掉杭州那条」 | 删掉相关记忆 |
| 「以后在这个群里你是个毒舌群友」 | 改这个会话的人设 |
| 「我们重新开始吧」 | 清空这个会话的上下文 |

实现方式是模型在回复里带 `<<remember: 内容>>` 这类标记，插件解析执行后把标记摘掉。
用户看到的还是正常的一句话。

### 接哪个 AI

**只接 DSH。** 插件不再自己调模型，也不再有 `适配器` 这个选项。

| 谁 | 干什么 |
|---|---|
| 这个插件 | 收 QQ 消息、判断该不该接、把结果发回去 |
| [dsh-roost](https://github.com/tdcq9594/dsh-roost) | 把消息交给 DSH 那一轮，拿回最终回复 |
| DSH | 模型、Key、工具、记忆、人格，全归它 |

想换模型？在 DSH 里换，这个插件一行都不用改。

宿主协议见 [AI宿主插件方案](../docs/AI宿主插件方案.md)。

## 它能发什么

走**官方接口**，比一般 QQ 机器人能做得多：

| 能力 | 说明 |
|---|---|
| **Markdown 真渲染** | 标题、列表、加粗、代码块、引用块都能显示出来（配置里 `markdown` 默认开） |
| **可点击按钮** | `<<button: 显示文字 \| 点了之后发的话>>`，一行最多两个、总共四个 |
| **图片** | `<<image: 网址或路径>>` —— **表情包、AI 画的图都走这条** |
| **语音** | `<<voice: 网址或路径>>` |
| **撤回**（4.2.0） | `<<retract>>` —— 把上一条自己发的收回来 |
| **文本链**（4.2.0） | `<qqbot-cmd-input>` 替对方把话打好、`<qqbot-at-user>` 在 markdown 里 @ 人 |
| **私聊流式**（4.3.0） | 长回复一条一条长出来，只占一条消息 |

按钮用的是**指令型**：点了等于用户自己发了那句话，所以它会自然流回正常对话，
不用单独处理点击事件。

这些能力都写进了系统提示词——**不写的话模型永远只会发纯文本**，
再好的接口也白搭。接 DSH 时这份提示词会一起送过去（payload 的 `system` 字段）。

一次最多发 3 个附件；扩展名有白名单（图片 png/jpg/gif/webp，语音 silk/amr/mp3/wav/ogg/m4a），
免得模型把别的文件当图发出去。

### 撤回（4.2.0）

模型在回复里带 `<<retract>>`，就能把**上一条**自己发的收回来——说错了、
语气不对、或者发完才发现不该说：

- 顺序是「先记住上一条是谁 → 再发这条 → 发完才撤」，撤的是它刚发的前一条
- 窗口 **110 秒**（官方给群消息 2 分钟，这里留了余量），超了就不撤——
  撤了也白撤，还多一次请求
- 标记本身不会发出去
- 撤不回来也不影响对话，只在日志里记一条

默认开，没有开关。

### 文本链（4.2.0）

官方支持在消息里嵌交互元素。这是**零指令**的关键——不用让人学怎么用：

| 标签 | 作用 |
|---|---|
| `<qqbot-cmd-input text="想说的话" />` | 替对方把话打好，他点一下就发出去（**只能私聊**，群里不生效） |
| `<qqbot-at-user id="他的 member_openid" />` | 在 markdown 消息里 @ 某个人 |

想让人接话又不知道怎么开口时用第一个：它问「要不要我展开讲讲」，
下面直接给一个填好的输入框，比说「你可以回复『展开』」自然得多。

### 私聊流式（4.3.0）

私聊里的长回复不再是一次性整段砸出来，而是**一条消息慢慢长出来**：

- 官方只有私聊的流式接口，**群聊没有**——所以群聊自动走普通发送，不用判断
- 带按钮时不流式：按钮只属于一条消息，切段的话按钮会挂到第一段上
- 切片之间停 140ms，否则「长出来」的过程肉眼看不见

**诚实说明**：DSH 给的是一次性完整文本，不是增量，所以底层是「分段推送」而不是真流式。
但因为是 replace 模式（服务端算差量），用户看到的是**一条消息在长出来**，不是刷屏。

失败了自动退回普通发送，不影响对话。

## 语音条（可选）

让 AI 说的话被**念出来**。要先在插件目录装三个纯 JS/WASM 的依赖：

```bash
cd <Roost 目录>/plugins/ai-chat
npm i @andresaya/edge-tts mpg123-decoder silk-wasm
```

然后在插件设置里把「语音音色」填成微软音色名，比如 `zh-CN-XiaoxiaoNeural`（女）
或 `zh-CN-YunxiNeural`（男）。留空 = 不开。

模型输出 `<<say: 要念的话>>` 就会发一条语音条。

**为什么绕这么大一圈**：QQ 官方语音要 **silk**，而 TTS 出来的都是 mp3，
所以中间转两道 —— 文字 → mp3 → PCM → silk。全在 Node 里跑，
**不要 Python、不要 ffmpeg、不要装服务**。

没装依赖、或者任何一步失败，都只是「这条没有语音」——文字照发，不影响对话。

## 它能看见什么

官方接口给的东西全都用上了，不是只读一段文本：

| 消息类型 | 它看到 |
|---|---|
| 语音 | **官方 ASR 转好的文字**（不用自己识别） |
| 图片 | 图片地址 |
| 引用 | 被引用的原文 |
| 合并转发 | 官方展开后的聊天记录 |
| 卡片（B站/小程序） | 卡片标题与链接 |

## 互动（4.2.0）

用户在面板或消息上点的东西，都会以 `INTERACTION_CREATE` 事件进来。
ai-chat 是**通道层**：负责鉴权 + 转发，真正的操作由 dsh-roost 执行。

| 类型 | 是什么 | 谁可以点 |
|---|---|---|
| 11 / 12 | 消息按钮 / 快捷菜单 | 主人、管理 |
| 13 | 点赞点踩 | 谁都可以 |
| 14 | 清空会话 | 只限主人 |
| 18 / 19 | 用户 / 群授权 | 谁都可以 |

三个不那么显然的取舍：

- **点赞点踩不鉴权**：那是表达态度，不是改配置。它直接喂进情绪系统——
  这是「被对待的反馈」最直接的来源
- **授权也不鉴权**：授权是用户处置自己的权利，谁点都算数。但必须记下来：
  群授权是**群主动消息的硬前置**，没这条记录群聊主动根本发不出去
- **鉴权失败静默丢弃**：群里绝不回「你没权限」——当众打脸 + 刷屏，只记日志

按钮的 `button_data` 约定格式是 `op|arg`，比如 `persona.set|毒舌群友`。

## 和别的插件一起用

- **不占任何指令**，不会跟 `/kun`、`/签到` 之类冲突
- 群聊里被别的插件回复过的消息，它可能也会接一句（框架会把多个插件的回复
  合并成一条，带【插件名】标题，不会混在一起）
- 不想让它在某个群说话：面板「插件 → 分群开关」里关掉就行

## 常见问题

**它一句话都不说**
1. 开放平台没开「接收所有消息」→ 只有 @ 才进得来
2. 没连上 DSH（dsh-roost 没装/没启动，此时只有 @ 它才会提醒你）
3. 冷却中 / 每分钟配额满了 → 开「调试日志」，日志里会写每条为什么没接

**它话太多**
把「什么时候接话」改成「只在被 @ 时说话」，或者调大冷却、调小每分钟上限。

**想让它在这个群换个性格**
直接说「以后在这个群里你是个……」；想看现在是什么，问它「你还记得什么」。
