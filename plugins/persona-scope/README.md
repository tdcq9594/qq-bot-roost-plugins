# 专属人设（persona-scope）

给**指定的人**（比如主人）单独换一套人设，其他人完全不受影响。

- 人设卡按 RP 卡的写法：分段落写角色、性格、说话方式，行文里可以夹**正则条件分支**
- 只对名单里的人（或达到某权限等级的人）生效，别人聊天还是原来的人设
- 不改全局人设，不接管消息 —— 只在这一轮消息里补一段设定，剩下的交给 AI 插件

---

## 它是怎么生效的

Roost 里人设本身由宿主侧负责（ai-chat 把 `system` 交给 DSH / webhook，人设来自 dsh-roost 的 `personas/*.md` + 按群覆盖）。插件之间没有「注入系统提示」这种通道。

所以这里走**监听器**（`ctx.on('message')`，`priority: 5`）：排在天气播报之后、AI 插件之前，只改写**命中者**这一轮的正文，把专属人设拼成一段带边界的指令块附在原文后面。

> 为什么不是中间件：`ctx.use` 的顺序由插件目录的加载顺序决定，跟 `priority` 无关。目录名排在前面时，在中间件里改正文会让**后面所有插件**都看到被拼了几百字人设的正文 —— reply-judge 会命中「你」字规则强行接话、天气插件因为超过 20 字不再出卡、trpg-forwarder 会把整段执事人设当行动文本发给守密人。改用监听器后靠 `priority` 精确落位：trpg-forwarder 60 → reply-judge 50 → weather-card 10 → **本插件 5** → ai-chat -100，别的插件看到的都是干净正文。

```
今天好累啊

〔专属人设·仅对本次发言人生效〕
角色：你是主任的专属执事，只对这个人用敬语。
用平静克制的语气。
〔专属人设结束〕
```

三个设计取舍：

| 取舍 | 理由 |
|---|---|
| 块放在原文**后面** | 前面的位置容易撞上别的插件的 `startsWith('/')` / 关键词判断；放后面原文一个字不动 |
| 不进系统提示 | Roost 没有这个通道；进用户消息是唯一通用做法，换 ai-chat / webhook / DSH 都一样有效 |
| 每轮重新注入 | 不依赖会话状态，换机器人、换宿主都不会丢 |

**代价说清楚**：它比真正的人设（系统提示）低一层权重，且每轮占一点 token（有上限）。要更强的人设请继续用宿主侧的 `personas/*.md`，这个插件负责「只对某个人」这层差异化。

## 配置

面板 → 插件 → 专属人设。

### 对哪些人生效

| 字段 | 说明 |
|---|---|
| `targets` | openid 列表，逗号/空格分隔。**只认 openid** —— 协议字段，改名、撞名都不影响 |
| `minLevel` | 或按权限等级：`0`=主人、`1`=管理员、`2`=群管、`3`=助手。与名单是「或」的关系 |

> 为什么坚决不认昵称：群名片随时能改，两个人同名很常见。一旦「名字像就算」，任何把名片改成主人名字的路人都能拿到专属设定 —— 这是权限差异，误认的代价远高于漏认。所以判定函数签名里根本没有能传名字的参数。

不知道自己/对方的 openid？让对方发 `/人设 我是谁`，机器人会把 openid 和权限等级回给本人。

### 其他开关

| 字段 | 默认 | 说明 |
|---|---|---|
| `enabled` | 开 | 关掉后完全不改任何消息 |
| `defaultCard` | 空 | 用哪套卡，空 = 数组第一套。**没有卡也能只用预设** |
| `maxChars` | 1200 | 注入长度上限。每轮都发出去，太长既费 token 又挤上下文 |
| `onlyWhenAddressed` | 关 | 只在对方 @ 机器人 / 私聊时注入（用框架的 `addressed`，含免@窗口） |
| `debug` | 关 | 把每次注入的块写进插件日志，调正则时开 |

### 人设卡（`cards`）

面板左侧 → 专属人设 → **人设卡** 页里管：列表、编辑、载入示例、导入导出。

点「载入示例」会插入随包附带的一张标准 RP 人设卡（基础信息 / 性格特征 / 说话风格 / 台词示例 / 扮演指导），照抄改内容即可。

```json
{
  "id": "arianna",
  "name": "爱莉安娜·哈特贝尔",
  "targets": "",
  "text": "# 角色设定：爱莉安娜·哈特贝尔 [恋人阶段]\n\n## 基础信息\n- **身份**：…目前是 {{user}} 的恋人。\n\n## 性格特征\n1. …"
}
```

- `text` 是正文，**条件分支用正则**
- 可选 `targets`：这一张只对这些人生效（实现「不同的人不同人设」），留空跟全局名单走

### 模板语法

| 写法 | 含义 |
|---|---|
| `{{if /正则/flags}}A{{else}}B{{end}}` | 正则命中走 A，否则走 B。`{{else}}` 可省略 |
| `{{if 早安\|早上好}}` | 不写 `/…/` 也当正则；写坏的会退化成「子串包含」 |
| 嵌套 | `{{if /a/}}A{{if /b/}}B{{end}}{{end}}` 支持 |
| `{{user}}` | **对方**（渲染成他的群昵称）—— 和 RP 卡的惯例一致 |
| `{{char}}` | 这张卡的角色名 |
| `{{nick}}` `{{time}}` `{{date}}` `{{weekday}}` `{{level}}` `{{chat}}` `{{cardName}}` `{{userId}}` | 其余变量。拼错的变量原样保留，不会静默变空白 |

> ⚠️ `{{user}}` 是**昵称**，不是 openid。照抄 SillyTavern 那类人设卡进来，`{{user}}` 会被正确替换成对方的名字；确实要 openid 才用 `{{userId}}`。

### 注入预算 `maxChars`（重要）

人设卡 + 已启用的预设，**每一轮**都会拼进消息发出去。`maxChars` 是这条的字符上限，超出从尾部截断——**卡片在前，所以先被砍的是预设**。

人设卡页顶部有实时预算条：「当前内容 N 字 / 预算 M 字」，超了变红并给出建议值。

怎么定：

| 场景 | 建议预算 |
|---|---|
| 只用人设卡、话不多 | 800 ~ 1200 |
| 标准 RP 人设卡（示例卡 1211 字） | 1500 ~ 3000 |
| 卡片 + 「破限」这类长预设（示例卡 1211 + 破限 3552） | **4900 以上** |

预算越大，每轮越费 token、越挤上下文——够用就好。

> 注意是**字符数**不是字节数。中文一个字按 1 算；那张示例卡 1211 字（UTF-8 下 2996 字节）。

条件匹配的对象是**这个人这一轮说的话**。所以人设卡可以写成「他说早安时我给晨间语气，说抱抱时我给亲昵语气」这种 RP 卡式的条件演出。

### 附加规则（已并入「预设管理」）

旧版的 `rules` 字段**已删除**，改成和 RP-Hub 一样的**预设管理页**：

> 面板左侧 → 专属人设 → **预设管理**

那一页可以：新建、拖动排序（也有 ↑↓ 按钮）、单条开关、编辑、删除、导入 / 导出 JSON。

每条预设：

```json
{ "name": "防抢话", "role": "system", "when": "", "content": "不得替对方补全言行。", "enabled": true }
```

| 字段 | 说明 |
|---|---|
| `name` | 列表上显示的名字，空的话按序号补 |
| `role` | `system` 系统提示词 / `user` User消息 / `assistant` AI消息 —— 和 RP-Hub 三档一致 |
| `when` | 生效条件（正则）。留空 = 总是生效 |
| `content` | 正文，支持 `{{变量}}` 与 `{{if}}` 条件 |
| `enabled` | 开关 |

**三种角色的区别**：`system` 拼进人设块（相当于附加约束）；`user` / `assistant` 会各自单独成段，并明确标注「模拟对方说的话」/「模拟你此前说过的话」—— 用于 RP 卡常见的破限预注入写法。标注是必须的，否则模型会把内容当成真实历史继续发挥。

升级时**旧 `rules` 会自动迁移成预设**，不会丢配置。

## 命令

| 命令 | 作用 |
|---|---|
| `/人设` | 看状态：几套卡、几条预设、生效对象 |
| `/人设 预览` | **看这一条消息会注入什么**（调正则最有用） |
| `/人设 测试 抱抱你` | 用给定句子走一遍真实拼装，看条件命中哪些 |
| `/人设 我是谁` | 查自己的 openid 与权限等级 |

预设的新建 / 排序 / 开关 / 导入导出都在面板的**预设管理**页；`/人设` 命令只负责查看和自测。

## 行为边界

- **只改正文，不改权限**：人设块只是给模型的话，不影响 `ctx.can` / `levelOf` 的任何判断
- **不接管消息**：不调 `msg.claim()`，要不要回、怎么回完全由 AI 插件决定
- **命令不注入**：`commandEntry` 存在的一律跳过，避免污染指令解析
- **幂等**：块带边界标记，重复经过会先剥离再加，不会一层层叠加
- **出错不吞消息**：监听器内部异常只记日志，本条按原样放行（没有 `next()`，也不影响别的插件）
- **正则风险**：正则由用户自己写在面板里、作用范围是本机人设卡，不存在被外部注入的路径。但写一个灾难性回溯的正则（如 `(a+)+$`）仍会拖慢这一条消息的处理 —— 建议先在 `/人设 测试` 里试

### 一个要留意的副作用

人设块是**拼进正文**的，所以别的插件看到的消息里会多出这段文字。若你的人设卡里刚好写了某个插件的关键词（比如卡里写了「天气」），而这个插件用「正文包含关键词」判定，就可能被误触发。

实际影响很小（触发者只有那个人自己，且注入后正文变长，多数关键词插件还有长度上限），但值得知道。真要避开，把人设卡里的词换掉，或者给那个插件改用更严格的触发条件。

## 开发与测试

```bash
# 在插件仓（qq-bot-roost-plugins）根目录执行
node --test "plugins/persona-scope/test/*.mjs"

# 若在当前插件目录（plugins/persona-scope）下执行
node --test "test/*.mjs"
```

改 `lib/card.js` 后需要**重启 Roost 进程**（热重载只对 `index.js` 生效）。相对 import 一律不带 `?v=` 查询串，避免同一模块被实例化两份。
