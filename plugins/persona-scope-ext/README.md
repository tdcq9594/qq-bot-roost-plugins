# 专属人设（persona-scope-ext）

把**某个人**绑到**某份人格**上：他走到哪个群都用这一套，其他人完全不受影响。

- 人设卡 + 预设 → 生成一份宿主人格 → 绑给某个 openid
- 走宿主的**按人指定人格**（`persona.bySender`），在**系统提示层**生效
- 可选**叠加入设成长**：把某个群长出来的习惯接在卡片后面，成长对绑定者也照样生效
- 与 Roost 插件 `persona-scope` **双向互通**（卡片、预设、正则条件都不丢）

| 项 | 值 |
|---|---|
| 版本 | 0.8.0 |
| 类型 | dsh-roost 扩展（`kind: dsh-extension`） |
| 权限 | `state:read`、`prompt:write` |
| 依赖 | dsh-roost ≥ 1.3.7（`persona.bySender`） |
| 定时任务 | 无 |

---

## 安装

把扩展目录放进数据目录，宿主会在面板里认出来：

```
<DSH 数据目录>/dsh-roost/extensions/persona-scope-ext/
├── plugin.json     清单
├── server.mjs      MCP 服务端（stdio）
├── actions.mjs     面板动作（inprocess）
├── page.html       面板页面
├── lib/            业务模块
└── README.md
```

启用后左栏出现「专属人设」。

## 权限

| scope | 为什么需要 |
|---|---|
| `state:read` | 读宿主人格库现状、成长扩展的状态 |
| `prompt:write` | 生成人格、按人绑定 |

安装时宿主会让你确认 `prompt:write`——能改提示词来源的扩展本来就能看到它。

## 怎么用

### 1. 人设卡

新建 → 填名字和正文（按 RP 卡写：角色 / 性格 / 说话方式 / 台词示例）。
每张卡有一个「**受人设成长影响**」勾选，默认关，说明见下面「叠加入设成长」。

### 2. 预设

可选。启用的预设按顺序接在卡片正文后面，一起生成人格。
典型用法：`不要替对方补全言行`、`不要用括号写动作`。

> 扩展的预设是**静态**的（启用就全拼上）。要 `{{if /正则/}}` 这种按当句话切换的，
> 用 Roost 插件版——它每条消息都判断一次。

### 3. 生成并绑定

填那个人的 openid → 点「生成并绑定」。
不知道 openid？让他在群里发 `/人设 我是谁`。

生成的人格在宿主人格库里能直接看到、能编辑。

### 4. 占位符（`{{user}}` 等）

人设卡里可以直接用 RP 卡的写法，**落库前会渲染成纯文本**：

| 写法 | 替换成 |
|---|---|
| `{{user}}` / `{{nick}}` | 「对方称呼」那一栏（默认「对方」）——也就是你在下面填的那个 openid 对应的人 |
| `{{char}}` / `{{cardName}}` | 卡片名 |
| `{{userId}}` | 那个人的 openid |
| `{{time}}` `{{date}}` `{{weekday}}` | **生成那一刻**的时间 |
| `{{if …}}A{{else}}B{{end}}` | 取 **B（else 分支）**：静态人格没有「当句话」可判 |
| 其他 `{{xxx}}` | **删掉**，并在预览结果里列出「未知占位符已移除」 |

> 为什么要渲染：人格正文会进 DSH 的系统提示，那边把 `{{…}}` 当**提示词变量**解析。
> 引用了没注册的变量会让整段渲染失败——这就是「卡片带 `{{user}}` 就报错」的原因。
> 现在扩展在建人格之前就把它们换成正文，宿主那边不再出现花括号。

### 5. 人格里混进了占位符（会「不说话」）

如果哪份人格带着 `{{…}}`（老版本生成的、或从别处导入的），DSH 的提示词渲染会失败，
表现是**整轮没有任何回复、也没有报错**。面板顶部会主动报出来：

> ⚠ 有人格带 `{{占位符}}`，它会让整轮对话没有任何回复 → 「一键修复」

修复就是把它们渲染成纯文本写回去（`{{user}}` → 「你」），宿主会自己留备份。

面板按钮会先弹确认框；MCP 的 `persona_scope_repair` **默认只报告**，
要落盘必须显式传 `dryRun: false`——批量改写宿主人格是破坏性动作，不该一个调用就发生。

### 6. 生成的人格 id

```
scope-<卡片id>[-grow-<群openid>]
```

- **≤ 60 字符**（宿主人格 id 上限）。卡片 id 太长时，卡片那一截换成 16 位哈希：
  `scope-<hash16>-grow-<群openid>`，正好 60 字符
- **群号永远完整保留**——它是唯一标识，截断必碰撞（曾经 6 位指纹在
  `31 个 C + 0` 与 `31 个 C + 1` 上撞过，导致已绑定用户读到另一个群的成长内容）
- **同卡同群幂等**：重复应用是更新，不会堆积人格

## 工具（MCP，9 个）

扩展不注册聊天命令，提供以下工具给模型调用：

| 工具 | 作用 |
|---|---|
| `persona_scope_list` | 卡片、预设、宿主人格、按人绑定、成长扩展状态 |
| `persona_scope_save_card` | 新建 / 修改人设卡（含「受成长影响」开关） |
| `persona_scope_save_preset` | 新建 / 修改预设 |
| `persona_scope_apply` | 卡片（含预设、可叠加成长）生成人格，可顺带绑定 |

| `persona_scope_bind` | 绑到已存在的人格 |
| `persona_scope_unbind` | 解除绑定 |
| `persona_scope_clear_growth` | 清除某个群的成长（需完整 32 位群号） |
| `persona_scope_import` | 从 Roost 插件导入卡片与预设 |
| `persona_scope_export` | 导出到 Roost 插件配置并让插件重载 |

## 叠加入设成长

「生成并绑定」时可以选择一个群，把**那个群的成长条目**接到卡片和预设后面：

```
卡片正文 → 预设 → 该群成长条目（## 慢慢长出来的习惯 …）
```

这样即使这个人被按人绑定（`bySender` 优先级高于按群的成长人格），**成长对他照样生效**。
生成的人格 id 带 `-grow-<群号>`，标签带「（含成长）」。

规则：

| 情况 | 行为 |
|---|---|
| 只有一个群在长 | 自动选它 |
| 多个群在长、没指定 | **拒绝执行**（不写人格、不绑定），提示去选群 |
| 一个都没有 | 明确说「还没有任何群长出条目」 |
| 成长文件损坏 | 安静退回「不叠加」 |

- 只读 `persona-grow` 的状态文件，**从不写它**（除了下面主动清除）
- **只叠加你选中的那个群**，不会把 A 群的习惯拼进 B 群
- 成长段默认上限 1600 字，超了截断

### 清除该群成长

面板上单独的按钮，也可以走 `persona_scope_clear_growth`：

- **只接受完整的 32 位群 openid**（不做前缀/后缀匹配——传 `"1"` 会直接报错，
  否则会把所有以 1 结尾的群一起清掉）
- 和 persona-grow **共用同一把锁**（`persona-growth.json.lock`），它正在写时我们等
- 清除时把该群的 `generation` **+1**：清除前启动、之后才返回的分析结果会因代际不符被丢弃
- 写前留 `.bak-<时间戳>` 备份

### 共存（不做叠加时）

| 扩展 | 写哪一层 | 优先级 |
|---|---|---|
| `persona-grow`（成长） | `persona.byChat[群]` | 低 |
| 本扩展 | `persona.bySender[人]` | **高** |

含义：某人被绑了专属人设后，那个群的**成长人格对他不生效**（被按人覆盖），
其他人照常。面板会列出「几个群在用成长人格、几个人被绑定」，要让成长对他生效
就解绑（或改用叠加）。

成长记录里 `personaId` 可能为空（persona-grow 0.5.0 起落地只记 `baseId`），
所以「是否生效」以**宿主此刻用的人格**为准：先取 `persona.byChat`，再查人格清单，
只有带 `growth`/`auto` 标签或名字含 `（成长）` 才算。因此「只有采样还没落地」
和「已切回普通人格」都不会误报。

## 每轮提示词注入（走插件）

扩展**没有每轮钩子**，做不到每条消息都改一次正文。要那个效果，接上 Roost 插件
`rp人设`：面板上「同步到插件并启用每轮注入」会

1. 把卡片与预设导出到插件配置（只改 `cards`/`presets`，其他设置原样保留）
2. **打开插件配置里的 `enabled`**
3. 打开框架的启用开关
4. 让插件重载配置

之后插件按自己的规则每轮注入——**包括 `{{if /正则/}}` 条件预设**，这部分扩展做不到。

注意这是**两个开关**：框架「启用插件」（把它加载起来）和插件配置里的 `enabled`
（它内部 `if (!c.enabled) return` 的闸门）。按钮会两个都打开并回读确认；
只开了框架开关时不会宣称「已开启」，而是明确告诉你还差插件内那个勾。

## 与 Roost 插件的关系

| 对比项 | 本扩展 | Roost 插件 `persona-scope` |
|---|---|---|
| 生效层 | **系统提示** | 消息正文（用户层） |
| 作用范围 | 这个人，跨所有群 | 指定群里指定的人 |
| 预设条件 | 静态 | `{{if /正则/}}` 按当句话判断 |
| 依赖 | 无 | 需要 AI 插件读 `msg.content` |
| 安装 | `extensions/` | `plugins/` |

**互通**：导入导出时，插件侧的 `content` / `when` / `role` / `targets` 会原样保留，
导回去不丢条件。导出只改 `cards` / `presets` 两个键，插件其他设置
（`maxChars`、全局名单）不碰；同 id 合并，插件独有的条目不会被删。

| 参数 | 同 id 时 |
|---|---|
| 默认导入 | **保留本地**，只补本地没有的 |
| `replace: true` | 用插件版本覆盖本地 |

面板写接口（重载 / 启用 / 写配置）都从框架的 `data/ports.json` 读端口，
**读不到就放弃并提示手动操作，绝不猜 8080**（那端口经常被别的软件占着）。
框架设了 `webui.accessKey` 时会自动带上 `X-Access-Key`；失败时提示里会写出
HTTP 状态（401 会明确说「访问密钥不匹配」）。

导出成功后会自动请求运行中的插件**重载配置**——不重载的话，插件内存里还是旧副本，
你下次在插件面板点保存就会把刚导出的卡片冲掉。多只机器人时重载请求带
`?bot=<机器人id>`，只重载**被写入的那一只**。

## 数据存哪

| 数据 | 位置 | 说明 |
|---|---|---|
| 人设卡 / 预设 | `<dsh-roost>/persona-scope-ext.json` | 素材，可导入导出 |
| 生成的人格 | 宿主人格库 `<dsh-roost>/personas/` | 产物，由宿主管理 |
| 绑定关系 | 宿主 `config.json` 的 `persona.bySender` | 卸载扩展**不会**自动清 |

写素材时有跨进程锁（面板动作与 MCP 子进程会同时写）。文件损坏时会保留
`.corrupt-<时间戳>` 备份并报错，不会被空库覆盖。宿主换发令牌后遇到 401 会
自动从 `secrets/` 读新令牌重试一次。

无。所有动作都由点击或工具调用触发。

## 已知边界

- **私聊**：宿主对一对一场景不贴发言者标签；本扩展依赖 `persona.bySender`，
  按人绑定在私聊里同样生效（`chatId` 就是对方 openid），但界面「解绑」需要
  openid，私聊场景请用 `/人设 我是谁` 或宿主面板查。
- **预设条件**：不支持 `when` 正则（扩展没有每轮钩子）。要条件分支请用插件版。
- **人格正文上限**：超过宿主人格正文上限（20 万字符）会被宿主拒绝，属预期。
- **依赖宿主补丁**：群会话复用时「按人绑定读到首轮发送者」是宿主侧的 bug，
  本地打了补丁（`host.js` 的 `mountedChat`）。宿主升级会覆盖它；升级后若发现
  按人绑定串到同群其他人，把补丁加回去即可。

## 卸载

面板卸载扩展即可。已写入的 `persona.bySender` 属于用户配置，不会自动清；
要清干净就对每个人执行一次 `persona_scope_unbind`。
