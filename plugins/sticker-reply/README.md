# 表情标注（sticker-reply）

版本：0.2.10。修复关闭状态迁移后误清理、图库链接目录校验遗漏，并统一保存目录与恢复默认的确认和迁移结果提示。

一套**表情库管理 + 标注 + 图库导出**工具，配合 Roost 内置表情功能，让机器人在「用一张图就能完整回应」的轮次只发图、不配字。

名字叫「表情标注」，因为它的主体是**标注工作**：图片先有含义、标签、适用与不适用场景，才会被导出给宿主，也才可能被选对。

---

## 一、功能

| 能力 | 说明 |
|---|---|
| **表情库管理** | 内置 14 张压缩 JPG（逐张写过初始标注）；可追加一个本地图片目录，两者合并 |
| **逐张标注** | 名称、含义、标签、适用场景、不适用场景、启用开关；支持搜索与四种筛选 |
| **稳定身份** | 按内容 SHA-256 认图：改名、移动、重复文件都归一；同内容不重复列 |
| **图库导出** | 把「已标注且启用」的图片导出成带标签的副本，文件名即标签，供内置表情功能读取 |
| **不覆盖你的文件** | 导出目录里非本扩展管理的同名文件、或被你改过的副本，一律保留并改用备用名；冲突出现在页面上 |
| **接入检查** | 四项状态一次看清：扩展已启用 / 图库已导出 / 内置表情已开启 / 目录已添加 |
| **辅助判断** | `sticker_decide` 工具：用一次独立模型会话判断这一轮能否只用一张图，返回文字方案或图片标记 |
| **匹配测试** | 面板里试一句话看判断结果与候选，**不向群里发消息** |

### 回复形态（约定，非强制）

| 场景 | 期望行为 |
|---|---|
| 情绪、问候、道谢、撒娇 | 只输出一个 `<<image-alone: 完整路径>>`，不配字、不写动作描写 |
| 知识、数据、命令、任务结果 | 正常回答 |
| 没有合适图片 | 正常说话，不勉强匹配 |

## 二、依赖

**硬依赖（不满足就不发图）**

| 依赖 | 说明 |
|---|---|
| **内置表情功能已启用** | 面板「表达 —— 表情包 —— 启用」，本扩展不替你开关 |
| 内置表情目录里**包含本扩展的导出目录** | 保留你原有的目录，多目录可共存 |
| 本扩展**已启用**且**已导出图库** | 面板顶部「接入内置表情」区检查 |

四项缺任一项，面板会直接指出缺哪一项（未开启时会提示「表达 —— 表情包 —— 启用」）。扩展只读配置做检查，不申请配置写权限。

**权限依赖**

| scope | 用途 | 性质 |
|---|---|---|
| `state:read` | 读接入状态、群信息、表情库 | 只读 |
| `agent:write` | 跑一次临时模型会话做辅助判断 | **敏感**，安装时单独确认，风险等级 2，会消耗模型额度 |

**软件依赖**

- 宿主 `dsh-roost` 提供 `/v1/config`、`/v1/agent.*`、`/v1/personas*`（仅读人格不写）
- 判断工具需要宿主默认模型可用；不可用时自动退回本地统计口径，不会卡住回复

**明确不依赖**

- 不修改宿主源码，不修改宿主配置，不创建或切换人格
- 不依赖任何待合的宿主改动

## 三、安装与接入（3 步）

| 步骤 | 操作 |
|---|---|
| 1 | 安装扩展，打开面板「表达 —— 表情标注」（就在「表情包」旁边）；若显示"扩展已关闭"，在「目录与设置」点**启用扩展** |
| 2 | 复制「接入内置表情」里的**图库目录**（默认位置，可改成别的绝对路径；改完点「保存目录」） |
| 3 | 到面板「表达 —— 表情包 —— 启用」打开开关，把该目录**加入目录列表** |

完成后点「检查接入状态」。

> 扩展安装或升级后需要重连 MCP 或重启 DSH，工具说明与 usage 才会刷新；只改标注不需要重启。

## 四、它怎么工作

```text
你标注图片  →  导出带标签图库  →  宿主内置表情写进提示词  →  模型直接写图片标记  →  宿主发送
                    ↑
              sticker_decide（可选）：模型拿不准时问扩展，扩展跑一次临时模型会话判断
```

- 图片发送完全走会话已有的图片通道，扩展自己不推送、不让模型填群号
- 判断规则：候选按标签/含义/场景筛到最多 24 张；置信度低于 0.8 不采用；库外 ID 直接拒绝；总超时 10 秒；失败、超时、非 JSON 一律退回文字；同会话最近三次尽量不重样

## 五、管理页面

面板位置：**表达 —— 表情标注**（与内置的「表情包」同一栏）。

| 区块 | 作用 |
|---|---|
| 接入内置表情 | 导出图库、显示目录、检查四项状态 |
| 表情列表 | 缩略图、名称、含义、来源、启用状态；筛选已标注/未标注/已禁用/来源失效，支持搜索 |
| 标注编辑 | 名称、含义、标签、适用/不适用场景、启用开关 |
| 目录与设置 | 额外图片目录、置信度阈值、候选上限、启用/关闭扩展 |
| 匹配测试 | 输入一句话看判断结果与候选，不发消息 |

图片预览按**已登记 ID** 取（返回 data URL），页面不访问本地任意路径。

## 六、图库导出规则

- 只有「填了含义且启用」的图片才导出
- 文件名 = `名称_标签…​_ID前12位.扩展名`，内置功能据此识别标签
- 首次需手动点「导出图库」；之后保存标注、保存设置、重新扫描会同步已发布副本
- 清理只针对**自己清单登记且内容仍一致**的副本；用户放进该目录的其他文件不动
- 关闭扩展会清空本扩展管理的副本，其他图库仍归宿主管理
- 来源原图始终只读

## 七、数据位置

```text
<DSH数据目录>/extension-data/sticker-reply/
├── annotations.json        用户标注（覆盖默认）
├── settings.json           扩展设置
├── recent.json             工具已选择记录（不是投递回执）
├── last.json               最近一次工具判断（内置直接选图不会写这里）
├── library/                默认图库目录（可在页面改成其他绝对路径）
│   └── .sticker-reply.json 导出清单（定向更新与清理用）
└── .write.lock             短时写入互斥
```

标注、设置和运行记录始终留在上述数据目录；自定义图库目录只存导出的图片与 `.sticker-reply.json` 清单。备份时一并保存自定义图库目录。删掉 `annotations.json` 等于回到默认标注；内置 14 张原图在 `assets/default/`，不受数据目录影响。

面板「保存目录」会把旧目录中清单登记且内容未改变的受管副本迁移到新目录，用户文件和修改过的副本留在旧目录；仅直接修改设置文件不会触发迁移。目标目录原先未受管的文件即使内容相同也不会被接管，会另取备用名；目标已受管的副本才参与去重。Windows 仅改变路径大小写视为同一目录。目录变更后仍需在宿主内置表情页面更新目录列表。

保存目录和恢复默认都先确认，并回显迁移、去重、冲突和留存结果。即使扩展已关闭，本轮迁移后也只读取状态，不再立即导出清理，刚搬到新目录的副本会保留；显式关闭、后续同步或手动导出仍遵循原清理规则。

图库目录本身及所有现存上级目录均须为普通目录：junction / 符号链接在校验、直接迁移和导出写入前都会被拦截，旧目录中的图片、清单和用户数据保留。

跨盘迁移逐文件执行复制和删除，不是整目录事务；中途出现 I/O 错误时可能已搬走部分文件，应保留新旧目录核对，过程不承诺自动回滚。

## 八、已知限制

1. **不能强制零文字**：宿主允许图文同条，扩展没有截断整轮输出的接口，模型仍可能配字或不用图。
2. **没有投递回执**：图片由会话既有通道发出，失败时扩展不知道，也不会自动补文字。
3. **没有后台自动判断**：所有判断都要有人（或模型）触发；`scanIntervalMs` 未接入定时扫描。
4. **内置直接选图不写扩展记录**：`last.json`/`recent.json` 只能证明工具被调用，不能用来判断内置发图是否发生。
5. **额外目录只读**：标注只存数据目录，不写回你的图片文件夹。
6. **来源失效的图会留在列表里**：文件被删后标注保留，可在「来源失效」筛选中查看；它们不参与导出与选图。
7. **标注文件异常会先备份**：解析失败、根值或 `images` 结构异常、版本不受支持时，会先原样备份成 `annotations.json.corrupt-<时间戳>-<唯一标识>.json` 再重建；唯一文件名和独占创建避免覆盖已有备份。
8. **平台侧失败不可见**：风控、权限或客户端差异导致的失败，扩展无法感知。

1. 在面板「表达 —— 表情包」的目录列表里**移除本扩展的图库目录**；
2. 卸载扩展；
3. 需要彻底清理时删除 `extension-data/sticker-reply/`。
