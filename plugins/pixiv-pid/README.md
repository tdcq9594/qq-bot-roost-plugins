# Pixiv 发图（pixiv-pid）

群里有人发 **「pid + 数字」**，机器人就把那张 Pixiv 作品取回来，图片和作品号一起发到当前会话。

```
群友：pid 98078015
机器人：[图片]  Pixiv #98078015 · 1600×2936 · 6623KB
```

## 安装

- **市场装**：面板 →「插件 → 市场」→ 搜「Pixiv 发图」→ 安装 → 刷新，`/pid`、`/pixiv` 立即可用。
- **手动装**：把整个 `pixiv-pid/` 目录放进 `roost/plugins/` 下，刷新面板即可。
- **不依赖任何东西**：没有 npm 依赖、不需要 ffmpeg 之类的外部程序，装完就能用；取图地址默认就是可用的那个，不用先配置。

## 怎么触发

一条消息里出现下面任意一种写法就行（不分大小写、加不加空格/冒号都认）：

| 写法 | 例子 |
| --- | --- |
| 前缀 + 号码 | `pid 98078015`、`PID:98078015`、`pid#98078015`、`pid98078015` |
| 中文前缀 | `作品号 98078015`、`插画号98078015` |
| 英文全称 | `pixiv id 98078015`、`illust id 98078015` |
| 作品链接 | `https://www.pixiv.net/artworks/98078015`、`https://www.pixiv.net/i/98078015`、`?illust_id=98078015` |
| pximg 直链 | `https://i.pximg.net/img-master/.../98078015_p0_master1200.jpg` |

不合规的写法不会被认（故意卡严的，否则一点风吹草动就发图）：

- 单独的纯数字（`20241103`、QQ 号、报价）；
- `apid 12345` 这种前面粘着字母的；
- `我的 id 12345678` —— 默认前缀里**没有**单独的 `id`，因为它太容易撞日常聊天。

一条消息里有多个 pid 时按顺序发，受「一条最多发几张」限制（默认 2）。

## 命令

| 命令 | 作用 | 权限 |
| --- | --- | --- |
| `/pid 98078015` | 手动按号码取图；可以一次给多个（空格分隔） | 所有人 |
| `/pid` | 用法提示 | 所有人 |
| `/pixiv` | 看状态：开关、缓存张数/占用、触发方式、本次运行的成功/失败/命中 | 所有人 |
| `/pixiv 清` | 清空本地图片缓存 | 管理员 |

指令不受「接话判断」那道闸门影响，任何时候都能用。

## 面板设置

面板 →「插件 → Pixiv 发图 → 设置」：

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| 启用 Pixiv 发图 | 开 | 关掉后既不听关键词，也不响应 `/pid` |
| 一条消息最多发几张 | 2 | 1–5。有人刷一串 pid 时只发前 N 张 |
| 图片带上作品号说明 | 开 | 说明文字和图片走**同一条**消息（依赖框架 ≥ 0.6.13） |
| 认 pixiv 作品链接 | 开 | 关掉后只认「前缀 + 号码」 |
| 触发前缀 | `pid,pixiv id,pixivid,作品号,插画号,illust id,illustid` | 逗号分隔，**用逗号隔，不要按空格拆**（`pixiv id` 是一个整体） |
| 取图地址模板 | `https://pixiv.re/{pid}.png` | `{pid}` 会被替换。⚠️ 别改成 `i.pixiv.re/{pid}.png`，那个域名只认带日期的完整路径，光给号码 404 |
| 下载超时（毫秒） | 20000 | 含**正文传输**时间，不只是等响应头 |
| 本地缓存上限（张） | 500 | 超了自动删最久没发过的 |
| 重复抑制（秒） | 60 | 同一张图在同一会话里 N 秒内再要一次就不理（防复读刷屏）；0 = 不抑制 |

## 取图链路（都是在这台机器上实测过的）

```
pixiv.re/{pid}.png        → 200 image/png|jpeg   ✅ 用这个
i.pixiv.re/{pid}.png      → 404                  ❌ 只认带日期的完整路径
api.lolicon.app 的 pids[] → 返回的是随机作品       ❌ 没法按 PID 反查标题
pixiv.net/ajax/illust/id  → 大陆直连不通           ❌ 不配代理用不了
```

所以说明文字只有**作品号 + 尺寸 + 文件大小**——这是能保证正确的部分。标题/画师要么拿不到，
要么拿到的可能是别人的作品（lolicon 的 `pids[]` 实测传 100000000 会返回一个完全不相干的
作品），与其贴错，不如不贴。

图片是**插件自己下载**的，不是把 URL 交给平台：

1. 平台下载失败时没有任何回调，群里只剩一句「发送失败」，查不出原因；
2. 图床出错时会返回一张 HTML 错误页，平台会把它当图片上传，发出去就是个坏图；
3. 下到本地才能校验 magic（真是不是图片）、读尺寸、复用缓存、限流。

## 数据与文件

- 代码：`plugins/pixiv-pid/index.js`
- 图片缓存：`data/bots/<bot>/plugins/pixiv-pid/pid-cache/<pid>.<ext>`
- 缓存索引：`data/bots/<bot>/plugins/pixiv-pid/pid-index.json`（原子写：先 `.tmp` 再改名）
- 配置：`config/bots/<bot>/plugins/pixiv-pid.json`
- 日志：`logs/bots/<bot>/plugins/pixiv-pid.log`

## 注意

- **和「接话判断」的关系**：那道闸门会先把不相关的群消息拦掉。reply-judge 的默认
  「放行正则」已经包含 `pid 12345678` / pixiv 链接这类写法，所以开箱即用；
  如果你把那条正则清空了，群里的 pid 消息就到不了这里（`/pid` 命令仍然可用）。
- 冷门作品第一次取图可能要 **20 秒左右**（pixiv.re 那边现拉现转），第二次走缓存秒回。
- 单张上限 20MB；图片超过 5MB 时框架会自动改用分片上传，不需要额外配置。
- 作品已删除 / 只允许登录查看（很多 R18 属于这类）时，pixiv.re 返回 404，
  插件会回一句「作品已删除，或者只允许登录后查看」，不会发坏图。
