# 人设生长（persona-grow）

按真实 QQ 会话里**有证据的行为**，慢慢长出一份「成长人格」，并把它切到那个会话上。

- 只统计她在真实对话里表现出的东西：口吻、称呼、习惯、偏好、情绪
- 每条成长都带**出处**（对话原文片段），编不出来
- 结果写成一份**派生人格**文件，原人格一个字节都不动
- 想还原随时一键切回，成长条目不会丢

## 权限

安装时声明 4 项：

| scope | 用途 |
|---|---|
| `state:read` | 读会话状态、群信息（群名） |
| `memory:read` | 读最近的对话记录（`GET /v1/journal`） |
| `agent:write` | 调一次模型做分析（`/v1/agent.new` → `prompt` → `close`） |
| `prompt:write` | 写派生人格并切换会话人格（`/v1/personas/create` + `/v1/session.configure`） |

其中 `agent:write` 与 `prompt:write` 在宿主里属于**敏感 scope**，安装时会单独要求主人确认——
它们分别对应「让模型跑一轮、烧额度」和「改人格」。不再申请用不到的 `session:write`。

## 数据存哪

- 成长状态：`~/.dsh/dsh-roost/persona-growth.json`（本扩展自持）
- 群名缓存：`~/.dsh/dsh-roost/persona-grow-names.json`
- 派生人格：宿主的人格目录下，形如 `<基人格>-grow-<会话指纹>.md`

**不依赖宿主的 `persona-growth` 端点**（那条接口在新版宿主里已经不存在了），
也不依赖任何待合的宿主改动：读写全部走公开的 `/v1` 接口。

## 怎么用

面板里选会话 → 三个按钮：

| 按钮 | 作用 | 花额度 |
|---|---|---|
| **预览分析（不写入）** | 只跑分析看会提炼出什么，**不改任何状态** | 会 |
| **立刻分析一次** | 分析 + 写成派生人格 + 把会话切过去 | 会 |
| **清空成长并还原人格** | 清空条目并切回原人格 | 不会 |

也可以在群里让她调工具：`persona_growth_status` / `persona_growth_grow_now` / `persona_growth_reset`。

## 关于「自动」

**没有后台自动分析。** 宿主不给扩展每轮钩子，分析必须有人（或模型调工具）触发。

面板上的进度是**真实**的：按这个会话最近的对话条数算，门槛默认 25 条。
到门槛会显示「已够，点下面『立刻分析一次』」——它只是建议，不会自己跑。

## 几条边界

- **采集范围**只到 `journal` 的保留期（默认 7 天），更早的对话取不到
- **写操作只认当前活跃会话**：群聊里模型若想把 chatId 填成别的群，会被拒绝
- **证据校验**：模型给出的每条都要在对话里找得到原文，找不到就丢弃
- **身份边界**：想改自称 / 改名 / 覆盖原人格的提议一律拒收
- **冲突优先级**：成长段与原人格冲突时，**以原人格为准**

## 已知限制

- **面板按钮有 30 秒上限**（宿主 `runInProcessAction` 的默认值）。所以模型调用超时压到 20 秒，
  超时自动退回本地统计（口癖、句尾、反问倾向等），不会让按钮报错。
- 私聊不参与：活跃会话按群算。
- 切换人格在 Roost 面板里做也可以；**切回原人格只是临时停用**，再分析会接上，条目不会丢。

## 卸载

在扩展列表里移除即可。已经生成的派生人格文件会留在人格目录里，
想彻底清掉就到人格列表里删掉 `*-grow-*` 那一份。
