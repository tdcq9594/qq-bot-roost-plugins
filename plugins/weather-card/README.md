# 天气播报（weather-card）

问一句「上海天气」或「今天天气怎么样」，机器人就回一张天气卡图片（一行一个地区：图标、当前温度、体感、湿度、风向风力、气压、日出日落、空气质量、宜/不宜），支持多地区、四大天气数据源与每日定时播报。

---

## 功能一览

- **多入口触发**
  - **自然语言关键词**：群里或私聊直接说「上海天气」「今天天气怎么样」「北京和杭州的天气」（短句 ≤20 字自动识别，不误插长句闲聊）
  - **斜杠指令**：`/天气 [地区...]`、`/天气 状态`、`/天气 绑定播报`、`/天气 取消播报`
  - **跨插件 AI 工具**：注册 `get_weather_card`，接入 AI 聊天插件后可由大模型按语境调用并附带结构化多日/逐小时摘要供追问
- **四套天气数据源（随时切换，换源即刻失效旧缓存）**
  - `wttr`：wttr.in（默认，免密钥开箱即用）
  - `openweather`：OpenWeatherMap（需 API Key）
  - `qweather`：和风天气（需 API Key + 专属 API Host，国内地名最准、支持到县级，含生活指数与空气质量）
  - `custom`：自建或其他 JSON 接口（自定义 URL 模板 `{region}` / `{key}` + 点号路径字段映射 + 自定义请求头）
- **独立展示开关**
  - 今日温度区间（`todayRange`）、未来三天预报（`forecast`）、未来 24 小时逐小时走势（`hourly`）、日出日落（`sun`）、今日宜/不宜生活指数（`indices`）、空气质量 AQI/PM2.5（`air`）各自独立开关
  - 深色（`dark`）/ 浅色（`light`）双主题
- **按量计费保护**
  - 针对和风天气等按量计费数据源，内置「城市坐标缓存 / 日出日落按日缓存 / 逐小时与空气质量按整点缓存 / 生活指数按日缓存」+ `dailyRequestLimit` 每日请求硬闸门
- **零依赖卡片渲染 + 文字兜底**
  - 自动寻找本机 Edge / Chrome 无头模式（`--headless=new`），先 `--dump-dom` 实测卡片真实高度再 `--screenshot` 出图（720@2x = 1440px 宽），不留底白、不截断、保留彩色 Emoji
  - 机器无浏览器或发图受限时自动回退结构化文字版天气卡
- **每日定时播报**
  - 支持多个时间点（如 `09:30,12:30,21:30`）自动推送到指定群（群内管理员发 `/天气 绑定播报` 一键登记群 `openid`）

---

## 用法

### 1. 直接问（免前缀）

```text
上海天气
今天天气怎么样
北京和杭州的天气
```

- 点名了地区就查点名的地区（最多同时 6 个）；没点名就查面板里配置的「默认地区列表」。

### 2. 命令

| 命令 | 说明 |
|---|---|
| `/天气` | 查默认地区列表的天气 |
| `/天气 上海 杭州` | 查指定地区（空格、逗号、顿号分隔均可） |
| `/天气 状态` | 查看当前数据源、默认地区、播报时间、浏览器状态与今日请求计数 |
| `/天气 绑定播报` | 群管理员在群内发送，把当前群 `openid` 登记进每日播报目标 |
| `/天气 取消播报` | 群管理员在群内发送，取消本群的每日天气播报 |

## 配置项（面板 → 插件 → 天气播报）

| 字段 | 默认值 | 说明 |
|---|---|---|
| `enabled` | `true` | 总开关 |
| `source` | `wttr` | 数据源：`wttr` / `openweather` / `qweather` / `custom` |
| `apiKey` | `""` | `openweather` / `qweather` / `custom` 使用的密钥 |
| `apiHost` | `""` | 和风天气专属 API Host（形如 `xxxx.re.qweatherapi.com`，必填，勿填已废弃的共享域名） |
| `dailyRequestLimit` | `300` | 每日 HTTP 请求上限（`0` = 不限，命中缓存不计数） |
| `apiUrl` | `""` | 自建接口 URL 模板，支持 `{region}`、`{key}` |
| `customMap` | `""` | 自建接口字段映射 JSON（如 `{"temp":"data.temp","text":"data.weather"}`） |
| `customHeaders` | `""` | 自建接口额外请求头，分号或换行分隔 |
| `cacheMinutes` | `15` | 同一地区缓存分钟数（最小 2，跨日自动失效） |
| `regions` | `"北京"` | 默认地区列表，逗号/顿号/分号/换行分隔，最多 6 个 |
| `todayRange` | `true` | 附带今日最高/最低温 |
| `forecast` | `false` | 附带未来三天预报 |
| `hourly` | `true` | 附带逐小时走势（地区 ≤3 个时展示） |
| `sun` | `true` | 附带日出日落时刻 |
| `indices` | `false` | 附带今日「宜 / 不宜」生活指数（和风天气 / 自建支持） |
| `air` | `false` | 附带空气质量 AQI 与 PM2.5（和风天气 / 自建支持） |
| `theme` | `dark` | 卡片配色：`dark` / `light` |
| `keywords` | `"天气"` | 免前缀触发关键词，逗号分隔；留空则仅响应 `/天气` 命令 |
| `cooldownSec` | `8` | 同一会话触发冷却秒数 |
| `broadcastTime` | `""` | 每日定时播报时间（如 `08:00,20:00`） |
| `broadcastTargets` | `""` | 播报目标群 `openid` 列表（推荐在群内用 `/天气 绑定播报` 自动登记） |
| `browserPath` | `""` | 自定义 Edge / Chrome 可执行文件路径，留空自动探测 |

## 开发与测试

### 改代码后怎么生效

| 改了哪里 | 生效方式 |
|---|---|
| `index.js` | 面板点「重载」即可（框架给入口加时间戳重新 import） |
| `lib/` 下任意文件 | **必须重启 Roost 进程**，热重载不会生效 |

`lib/` 内部和入口的 import **都不带 `?v=N` 查询串**，这是刻意的：

- 带查询串会让同一个文件被 ESM 当成两个模块各实例化一份。`sources.js` 里有 5 个模块级缓存 Map（按量计费靠它们省请求），一旦分裂成两套，同一地区同一小时可能走不同缓存路径、多打一次接口。
- 而「改 lib 就递增入口 `?v=N`」这个约定并不能解决问题：递增只会重新加载 `render.js`，它内部那句 `./png.js` 的 URL 始终不变，照样命中旧模块。四个文件互相引用，靠手工递增必然漏一个。

所以选择统一不带查询串（每个模块全局只有一个实例），代价是改 `lib/` 要重启进程。`test/module-identity.mjs` 会断言「相对 import 不许带查询串」，防止以后又写回去。

### 跑测试

```bash
# 在框架仓根目录（qq-bot-roost）执行
node --test "plugins/weather-card/test/*.mjs"
```

三个文件：`basic.mjs`（纯函数）、`regressions.mjs`（已修 bug 的回归）、`module-identity.mjs`（模块身份与清单契约）。

⚠️ 测试里的 import 必须与 `index.js` 的 specifier **完全一致**。带不带查询串在两个模块实例之间，用错会造成「打桩无效、请求真发出去」的假象。

### 框架版本要求

`frameworkVersion: '>=0.8.6'` —— `ctx.registerTool`（跨插件 AI 工具）是框架 0.8.6 才引入的（见 `RELEASE_NOTES.md` v0.8.6）。

声明低了不会崩，但 AI 工具**静默不注册**：用户看到的是「装上了，AI 却不会查天气」，且没有任何报错。所以直接在清单里卡住，低于 0.8.6 拒绝加载并显示版本不符。
