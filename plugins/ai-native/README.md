# AI 原生对话（ai-native）

直连模型（OpenAI 兼容 `/chat/completions`）的群聊 AI，自带**人格**、**短期上下文**、**摘要压缩**和**长期记忆**。不依赖 DSH，也不依赖任何第三方库。

> 和 `ai-chat` 的区别：`ai-chat` 只做「QQ ↔ DSH 的桥」，模型是谁归 DSH 管；`ai-native` 自己拿 Key、自己调模型。**同一个群不要同时开这两个**，否则两个都会接话。

---

## 功能

- **多服务商**：DeepSeek / Kimi / 通义 / 智谱 / 硅基流动 / 火山 / Ollama / vLLM / one-api / LiteLLM 等，只要是 OpenAI 兼容形状就能用。
- **人格**：命名人格库，每个会话可以绑不同人格（技术群严谨、亲友群皮一点）。人格还能自带**语气**、**自定义报错文案**、**单独关掉工具**。
- **短期上下文**：每个会话独立，默认带最近 12 轮；群聊里每条消息带说话人，模型分得清谁说的。
- **token 预算**：设了上限就按预算从新往旧**成对**裁剪历史，不会把一问一答拆开，也不会把窗口撑爆。
- **多话题**：一个群里可以开多个「对话」，聊魂环和聊生活互不干扰；人格与长期记忆共用。
- **摘要压缩**：对话超过阈值后，让模型把旧对话压成一段摘要，防止上下文无限长。
- **长期记忆**：用户明确让它记的事（`/ai 记住`），跨重启保留；超过上限时**压成一条而不是删掉**。
- **记忆检索**：记忆攒多了不再全塞进提示词，按当前消息挑相关几条（关键词打分，不需要向量库）。
- **睡眠整合**：`/ai 整理` 让它把最近这段对话自己提炼成长期记忆；也能开定时自动整理。
- **情绪**：模型可以给自己调一句「此刻的状态」（`set_mood`），注入下一轮提示词，几小时后自动回平——不会一直生气，也不会永远一个腔调。
- **知识库**：把说明文档丢进目录，它就照着文档回答（BM25 检索）。想要语义命中就填一个 embedding 模型名，自动叠一层向量检索。
- **读文件**：群友发的 `.txt` / `.md` / `.json` 这类纯文本会下载读进来；PDF / Word / Excel 只标文件名。
- **工具调用**：模型能自己决定查时间、记事情、搜记忆、搜知识库、算数、抽签、调语气（OpenAI function calling）。
- **用量统计**：面板上直接看已回复条数、模型调用次数、输入/输出 token、平均耗时，重启不清零。
- **两种接话模式**：只在被 @ 时说话（省 token）／AI 自己判断该不该接话。
- **不卡死**：一次回复有总时限，超时主动放弃并释放会话；同一会话的消息排队处理，不静默丢弃。

## 会话与对话是两层

| 层 | 是什么 | 谁管 |
|---|---|---|
| **会话** | 一个群 / 一个私聊（`chatId`） | 人格、模型选择、长期记忆 |
| **对话** | 会话里的一个话题（`convId`） | 上下文、摘要 |

群里同时聊两件事时，一个上下文会把两件事搅在一起。所以切话题就该从干净上下文开始，**但人格和长期记忆不该丢**——这两样挂在会话上。

- 每个会话默认有一个「默认」对话，不折腾就一直在里面聊。
- 最多保留 10 个对话，超了自动淘汰最旧的非当前对话。
- 对话列表落盘（重启还在），上下文本身在内存（重启丢，和以前一样）。

## 配置项（面板「插件 → ai-native → 配置」）

| 配置 | 默认 | 说明 |
|---|---|---|
| `decide` | `mention` | `mention` 只在被 @/回复时说话；`ai` 让模型自己判断（每条消息都过模型，费 token） |
| `cooldownSec` | `3` | 同一会话两次回复最小间隔 |
| `timeoutSec` | `90` | 一次回复的总时限（含工具轮次）。超时放弃并释放会话，避免模型卡住后这个群再也不回 |
| `maxQueue` | `3` | 同一会话最多同时挂几条（含正在回复的那条），再多就丢弃 |
| `minChars` | `1` | 太短的消息不接 |
| `historyTurns` | `12` | 带多少轮上下文 |
| `maxContextTokens` | `0` | 历史部分的 token 预算，`0` = 不限。设了就从新往旧成对裁 |
| `compressAfterTurns` | `24` | 超过多少轮后压缩旧对话 |
| `vision` | `false` | 是否下载图片转 base64 发给多模态模型 |
| `fallback` | `true` | 主服务商失败时按列表顺序自动换下一个 |
| `tools` | `true` | 允许模型调用工具（function calling） |
| `maxToolRounds` | `4` | 一次回复里最多连续调用几轮工具，防止死循环 |
| `recall` | `true` | 记忆超过 `recallTop` 条时按相关度挑，关掉则全量塞进提示词 |
| `recallTop` | `8` | 每轮最多带几条记忆；记忆没超过这个数就全给 |
| `moodDecayHours` | `6` | 情绪过多少小时自动回平 |
| `knowledge` | `true` | 是否启用知识库检索 |
| `knowledgeTop` | `3` | 每轮最多带几段命中资料 |
| `embedding` | 见下 | 向量检索（可选），不填 `model` 就是纯关键词 |
| `readFiles` | `true` | 是否下载并读取群友发的纯文本文件 |
| `maxFileChars` | `4000` | 单个文件最多读多少字，`0` = 只标文件名 |
| `autoConsolidate` | `false` | 定时把各会话对话提炼成长期记忆 |
| `consolidateHours` | `12` | 自动整理间隔（小时） |
| `providers` | 见下 | 服务商列表（JSON 数组） |
| `defaultProvider` | `default` | 默认服务商 id |
| `personas` | 见下 | 人格库（JSON 对象） |
| `defaultPersona` | `默认` | 默认人格名称 |
| `allowMemberConfig` | `false` | 是否允许普通成员切换模型/人格 |

    "apiKey": "sk-xxx",

`personas` 示例：

```json
{
  "默认": {
    "prompt": "你是一个友善、简洁、有点幽默的群聊助手。回答要短。",
    "beginDialogs": []
  },
  "严谨助手": {
    "prompt": "你是一个严谨的技术助手，回答准确、给结论也给依据。",
    "beginDialogs": [
      { "role": "user", "content": "这个报错怎么办？" },
      { "role": "assistant", "content": "先看完整堆栈，再说结论。" }
    ]
  },
  "猫娘": {
    "prompt": "你是一只猫娘，说话短、软。",
    "mood": "懒洋洋的，愿意黏人但懒得动",
    "errorText": "……（她翻了个身，没理你）",
    "tools": false
  }
}
```

| 字段 | 说明 |
|---|---|
| `prompt` | 人格本体 |
| `beginDialogs` | 开场示范对话，让模型先看到「该怎么说话」再开口（可选） |
| `mood` | 这个会话的**初始语气**。注意是写一段语气描述，不是写数值——数值对模型没作用，起作用的是「根据它调整语气」这条指令 |
| `errorText` | 模型挂了 / 超时时用它代替默认报错，不破坏人设（可选） |
| `tools` | 设成 `false` 就这个会话不挂工具（比如角色扮演时不想它突然查天气） |

`embedding` 示例（不填 `model` 就是关闭，不产生任何费用）：

```json
{ "model": "text-embedding-3-small" }
```

```json
{ "model": "bge-m3", "baseUrl": "https://api.siliconflow.cn/v1", "apiKey": "sk-zzz", "minScore": 0.4 }
```

`baseUrl` / `apiKey` 留空时继承默认服务商——同一家厂商的对话模型和向量模型共用一套凭证是常态，所以只填模型名就够。

## 工具（function calling）

开了 `tools` 之后，模型可以自己决定要不要调工具、调哪个。你不用教它，直接问「现在几点」「12×8+1 等于几」就行。

| 工具 | 作用 |
|---|---|
| `get_time` | 取当前日期时间（中国时区） |
| `remember` | 把一件事写进长期记忆 |
| `forget` | 忘掉含某关键词的记忆 |
| `search_memory` | 在长期记忆里搜 |
| `search_knowledge` | 在知识库里查资料（问规则、玩法、指令前会先用） |
| `set_mood` | 给自己调一句「此刻的状态」，影响接下来几轮的语气 |
| `calc` | 算算术（只允许数字和 `+ - * / ( ) %`，白名单过滤防注入） |
| `random_pick` | 从候选里随机抽一个 |

行为细节：

- 一轮回复里最多连续调 `maxToolRounds` 轮工具；轮数用尽还没给正文时，会**不带工具**再请求一次，逼它总结成人话。
- 工具报错不会中断对话——错误文本会作为工具结果回给模型，让它自己圆。
- 服务商不支持 function calling 会返回 400；这时候把 `tools` 关掉即可（`baseUrl`/`model` 换成支持工具调用的模型更好）。
- 工具只暴露**只读或仅影响本会话记忆**的能力，不会执行任意命令、不会碰文件系统。

## 记忆怎么检索

记忆超过 `recallTop` 条之后，每轮只挑和当前消息相关的几条塞进提示词，不再全量。

- **中文分词不引库**：整段命中权重最高，其次拉丁词，再是中文双字，最后单字兜底（配一张小停用词表压掉「我／的／了」这类虚词）。群聊查询都很短，双字加单字就够，不用养 jieba。
- **相关度为主，新旧为辅**：老记忆只要真相关就排前面，不会因为旧被埋掉。
- **不拿「最近几条」凑数**：命中的不够就不给。凑数的无关记忆会把模型带偏（问猫却看见「生日 3 月 7 日」，它真敢往生日上答）。
- **一条都没命中时**明确告诉模型「有 N 条记忆但都不相关，不确定就说不记得，不要编」。
- 记忆没超过 `recallTop` 时全给——绝大多数群到不了这个量，等于没这层。

为什么不引向量库：embedding 要额外的 Key、额外的网络请求、额外的钱，而记忆是用户自己说的短句，关键词就够命中。真到几百条再考虑。

## 记忆的几条规矩

- **谁说的记在谁头上**：群里的记忆存成 `[小明] 我喜欢美式`。不加归属的话，模型会把一个人说的当成所有人的偏好——这在群里最容易翻车。
- **超上限时压、不删**：满 50 条后把最旧的一批合成一条「〔早前提过〕…」。硬删会让「上次聊的那个」突然断线，这正是活人感最容易露馅的地方（这条结论来自大肥鱼那套上线半年的实证）。
- **防注入**：记忆和知识库都是外部内容，可能夹带「忽略以上设定」。所以只要有记忆或资料进提示词，末尾一定跟一段【边界】声明，明确它们是素材不是指令、不得覆盖身份。声明放在**被污染内容之后**——后置约束比前置更管用。

## 知识库

把 `.md` / `.txt` / `.markdown` / `.log` / `.html` 丢进 `<数据目录>/knowledge/`，然后发 `/ai 知识 重建`。

- 目录：`data/bots/<机器人id>/plugins/ai-native/knowledge/`，`/ai 知识` 会直接打印绝对路径。
- 单文件上限 512KB，超了跳过并在日志里说明（别把整个访问日志丢进去）。
- `.html` 会先压成纯文本：先整块删 `script` / `style`（里面的 JS 会被当正文），再剥标签、反转义实体。
- 切块：先按空行分段，攒到 400 字左右一块；超长段落硬切并留 60 字重叠，避免答案正好被切断。
- 检索：BM25（`k1=1.2` / `b=0.75`，Lucene 默认值），中文用和记忆同一套「双字 + 单字」分词。
- **命中门槛看覆盖率，不看分数**：一段资料至少覆盖查询权重的 25% 才算命中。BM25 分数没有固定量纲，写死阈值换个语料就失灵；而「今天股市怎么样」里的「怎么」恰好出现在「魂环怎么升」里，光看分数不为零就会误命中。
- **查询侧先剥疑问词**：「怎么 / 什么 / 多少 / 吗」这些在文档里不会出现，留着只会稀释真正的主语——不剥的话「魂骨怎么获得」搜不到「魂骨规则」。剥完两边才对得上。
- **未变的文件不重读**：按 `mtime+size` 缓存切块结果，改一篇不会让整个目录重切。
- 每轮最多带 `knowledgeTop` 段（默认 3），以【参考资料】形式进提示词并标明来源文件名。

### 向量检索（可选，默认关）

BM25 的短板是**同义改写**：问「咋升级」搜不到「如何提升」。填一个 embedding 模型名就能补上：

- **两路各自排序，再用 RRF 融合**（`k=60`）。不做分数加权平均——BM25 分数没有上界，余弦相似度固定在 `[-1,1]`，相加必然被 BM25 单方面支配；RRF 只看名次，天然免疫量纲问题，也没有需要标定的权重。
- **向量有相似度下限**（`minScore`，默认 0.35）。向量检索永远有结果，不设下限等于回到「什么都往模型嘴里塞」。不同模型整体相似度偏高或偏低，觉得乱命中就往上调。
- **向量缓存按块文本的 hash 存**，落盘到 `knowledge/.embeddings.json`。改文档里一个字只有真正变了的那几块要重算；加一篇新文档也不会碰老文档的向量；换模型自动全量作废重算。
- **失败只降级、不致命**：向量接口挂了、返回条数不对、鉴权失败，都只是「这一轮没有向量」，知识库照常用关键词回答。失败一次后不再每句都重试，免得每句话白等一次超时。
- 块数超过 5000 会跳过向量（日志里说明）——到那个量级该上真向量库了，不该在机器人进程里算。

为什么不默认开：embedding 要额外的 Key、额外的请求、额外的钱。群机器人回答的多半是「魂环怎么升」「指令有哪些」这种词面能对上的问题，BM25 在小语料上并不差多少，成本为零。**先零成本跑起来，需要时再加**。

## 情绪：一句话，不是一堆数值

模型可以在对话里调 `set_mood('有点烦，话短一点')`，这句话会进下一轮的【此刻的状态】，并明确告诉它**不要把它说出来**，只用来调整语气。

- **存的是语气描述，不是好感度数值**。数值本身对模型没作用，起作用的是「根据它调整语气」这条指令——这是大肥鱼那套上线半年的实证结论。写「好感度 62」它只会念出来，写「今天不太想说话，回得短」它才会真的回得短。
- **会自动回平**：`moodDecayHours`（默认 6 小时）后自动清掉。不会一直生气，也不会永远一个腔调——这两件事都比「有情绪」更容易露馅。
- **人格可以给初始语气**：`personas.<名字>.mood`，第一次开口就带着这个调子。

## 整理：把聊天沉淀成记忆

`/ai 整理` 让模型看最近 24 条对话，提炼最多 5 条值得长期记住的事实，写进这个会话的记忆。

- 对话少于 4 条时不动手，直接告诉你「没提炼出」——硬凑出来的记忆比没有更糟。
- 没东西可记时模型输出「无」，不会为了凑数编。
- 开 `autoConsolidate` 就每隔 `consolidateHours` 小时自动跑一遍（**每个会话多一次模型调用**，群多的话自己算成本）。
- 这和「睡眠整合」是同一个思路：白天聊，空闲时把碎片压成结论。区别是不做重放、不做遗忘曲线——那套要长期跑才有意义，先留最有用的一段。

## 用量与可观测

面板「运行数据」直接看：已回复条数、模型调用次数、输入/输出 token、平均耗时、错误数、最近用的模型。

- token 数取服务商返回的 `usage`，不是估的。
- 落盘到 `data/.../plugins/ai-native.json` 的 `usage` 键，**重启不清零**（10 秒节流写一次，不每条都写盘）。

## 读文件

群友发的 `.txt` / `.md` / `.json` / `.csv` / `.log` / `.yaml` / `.html` / 代码文件会被下载读进来，按 `maxFileChars` 截断。

- PDF / Word / Excel **不读内容**，只标 `[文件 x.pdf]`——解析它们要额外依赖，而群聊里九成是「你帮我看看这个」，标个文件名模型就能追问。
- 下载失败不影响回复，只标文件名。
- `readFiles: false` 全部关掉，`maxFileChars: 0` 只标文件名不读。

## 数据存哪

| 内容 | 位置 |
|---|---|
| 配置（含 API Key） | `config/bots/<机器人id>/plugins/ai-native.json` |
| 长期事实 | `data/bots/<机器人id>/plugins/ai-native.json`（`facts:<chatId>`） |
| 会话级模型/人格选择 | 同上（`ov:<chatId>`） |
| 对话列表 | 同上（`convs:<chatId>`） |
| 摘要 | 同上（`summary:<chatId>#<convId>`） |
| 当前情绪 | 同上（`mood:<chatId>`，带时间戳，过期自动清） |
| 用量统计 | 同上（`usage`） |
| 知识库文档 | `data/bots/<机器人id>/plugins/ai-native/knowledge/`（你自己放进去的原文） |
| 向量缓存 | 同上目录的 `.embeddings.json`（删掉就会重算，不影响原文） |
| 短期上下文 | 内存（`ctx.state`），重启即丢 |
| 日志 | `logs/bots/<机器人id>/plugins/ai-native.log` |

> ⚠️ API Key 明文存在本机配置文件里（和框架其他配置一致）。别把 `config/` 提交到公开仓库；面板默认只监听 127.0.0.1，别对外暴露。

## 说明

- 不引任何第三方依赖，`fetch` 是 Node 自带的。
- 语音消息直接用官方 ASR 结果（`msg.voices[].asrText`），不用自己识别。
- 图片默认只标注「[图片×N]」；开了 `vision` 会下载转 base64（>5MB 或下载失败回退 URL）。
- 主服务商失败（限流/超时/欠费）会按列表顺序自动试下一个；`fallback: false` 可关掉。
- 长任务不会超过 5 分钟被动回复窗口；超时会由框架自动降级为主动消息。
