# AI 原生对话（ai-native）

直连模型（OpenAI 兼容 `/chat/completions`）的群聊 AI，自带**人格**、**短期上下文**、**摘要压缩**和**长期记忆**。不依赖 DSH，也不依赖任何第三方库。

> 和 `ai-chat` 的区别：`ai-chat` 只做「QQ ↔ DSH 的桥」，模型是谁归 DSH 管；`ai-native` 自己拿 Key、自己调模型。**同一个群不要同时开这两个**，否则两个都会接话。

---

## 功能

- **多服务商**：DeepSeek / Kimi / 通义 / 智谱 / 硅基流动 / 火山 / Ollama / vLLM / one-api / LiteLLM 等，只要是 OpenAI 兼容形状就能用。
- **人格**：命名人格库，每个会话可以绑不同人格（技术群严谨、亲友群皮一点）。
- **短期上下文**：每个会话独立，默认带最近 12 轮。
- **多话题**：一个群里可以开多个「对话」，聊魂环和聊生活互不干扰；人格与长期记忆共用。
- **摘要压缩**：对话超过阈值后，让模型把旧对话压成一段摘要，防止上下文无限长。
- **长期记忆**：用户明确让它记的事（`/ai 记住`），跨重启保留。
- **记忆检索**：记忆攒多了不再全塞进提示词，按当前消息挑相关几条（关键词打分，不需要向量库）。
- **知识库**：把说明文档丢进目录，它就照着文档回答（BM25 检索，同样不需要向量库）。
- **工具调用**：模型能自己决定查时间、记事情、搜记忆、算数、随机抽（OpenAI function calling）。
- **两种接话模式**：只在被 @ 时说话（省 token）／AI 自己判断该不该接话。

## 会话与对话是两层

| 层 | 是什么 | 谁管 |
|---|---|---|
| **会话** | 一个群 / 一个私聊（`chatId`） | 人格、模型选择、长期记忆 |
| **对话** | 会话里的一个话题（`convId`） | 上下文、摘要 |

群里同时聊两件事时，一个上下文会把两件事搅在一起。所以切话题就该从干净上下文开始，**但人格和长期记忆不该丢**——这两样挂在会话上。

- 每个会话默认有一个「默认」对话，不折腾就一直在里面聊。
- 最多保留 10 个对话，超了自动淘汰最旧的非当前对话。
- 对话列表落盘（重启还在），上下文本身在内存（重启丢，和以前一样）。

## 配置项（面板「插件 → ai-native → 配置」）

| 配置 | 默认 | 说明 |
|---|---|---|
| `decide` | `mention` | `mention` 只在被 @/回复时说话；`ai` 让模型自己判断（每条消息都过模型，费 token） |
| `cooldownSec` | `3` | 同一会话两次回复最小间隔 |
| `minChars` | `1` | 太短的消息不接 |
| `historyTurns` | `12` | 带多少轮上下文 |
| `compressAfterTurns` | `24` | 超过多少轮后压缩旧对话 |
| `vision` | `false` | 是否下载图片转 base64 发给多模态模型 |
| `fallback` | `true` | 主服务商失败时按列表顺序自动换下一个 |
| `tools` | `true` | 允许模型调用工具（function calling） |
| `maxToolRounds` | `4` | 一次回复里最多连续调用几轮工具，防止死循环 |
| `recall` | `true` | 记忆超过 `recallTop` 条时按相关度挑，关掉则全量塞进提示词 |
| `recallTop` | `8` | 每轮最多带几条记忆；记忆没超过这个数就全给 |
| `knowledge` | `true` | 是否启用知识库检索 |
| `knowledgeTop` | `3` | 每轮最多带几段命中资料 |
| `providers` | 见下 | 服务商列表（JSON 数组） |
| `defaultProvider` | `default` | 默认服务商 id |
| `personas` | 见下 | 人格库（JSON 对象） |
| `defaultPersona` | `默认` | 默认人格名称 |
| `allowMemberConfig` | `false` | 是否允许普通成员切换模型/人格 |

`providers` 示例：

```json
[
  {
    "id": "default",
    "name": "DeepSeek",
    "baseUrl": "https://api.deepseek.com/v1",
    "apiKey": "sk-xxx",
    "model": "deepseek-chat",
    "maxTokens": 1024,
    "temperature": 0.7
  },
  {
    "id": "qwen",
    "name": "通义千问",
    "baseUrl": "https://dashscope.aliyuncs.com/compatible-mode/v1",
    "apiKey": "sk-yyy",
    "model": "qwen-plus"
  }
]
```

`personas` 示例：

```json
{
  "默认": {
    "prompt": "你是一个友善、简洁、有点幽默的群聊助手。回答要短。",
    "beginDialogs": []
  },
  "严谨助手": {
    "prompt": "你是一个严谨的技术助手，回答准确、给结论也给依据。",
    "beginDialogs": [
      { "role": "user", "content": "这个报错怎么办？" },
      { "role": "assistant", "content": "先看完整堆栈，再说结论。" }
    ]
  }
}
```

## 工具（function calling）

开了 `tools` 之后，模型可以自己决定要不要调工具、调哪个。你不用教它，直接问「现在几点」「12×8+1 等于几」就行。

| 工具 | 作用 |
|---|---|
| `get_time` | 取当前日期时间（中国时区） |
| `remember` | 把一件事写进长期记忆 |
| `forget` | 忘掉含某关键词的记忆 |
| `search_memory` | 在长期记忆里搜 |
| `search_knowledge` | 在知识库里查资料（问规则、玩法、指令前会先用） |
| `calc` | 算算术（只允许数字和 `+ - * / ( ) %`，白名单过滤防注入） |
| `random_pick` | 从候选里随机抽一个 |

行为细节：

- 一轮回复里最多连续调 `maxToolRounds` 轮工具；轮数用尽还没给正文时，会**不带工具**再请求一次，逼它总结成人话。
- 工具报错不会中断对话——错误文本会作为工具结果回给模型，让它自己圆。
- 服务商不支持 function calling 会返回 400；这时候把 `tools` 关掉即可（`baseUrl`/`model` 换成支持工具调用的模型更好）。
- 工具只暴露**只读或仅影响本会话记忆**的能力，不会执行任意命令、不会碰文件系统。

## 记忆怎么检索

记忆超过 `recallTop` 条之后，每轮只挑和当前消息相关的几条塞进提示词，不再全量。

- **中文分词不引库**：整段命中权重最高，其次拉丁词，再是中文双字，最后单字兜底（配一张小停用词表压掉「我／的／了」这类虚词）。群聊查询都很短，双字加单字就够，不用养 jieba。
- **相关度为主，新旧为辅**：老记忆只要真相关就排前面，不会因为旧被埋掉。
- **不拿「最近几条」凑数**：命中的不够就不给。凑数的无关记忆会把模型带偏（问猫却看见「生日 3 月 7 日」，它真敢往生日上答）。
- **一条都没命中时**明确告诉模型「有 N 条记忆但都不相关，不确定就说不记得，不要编」。
- 记忆没超过 `recallTop` 时全给——绝大多数群到不了这个量，等于没这层。

为什么不引向量库：embedding 要额外的 Key、额外的网络请求、额外的钱，而记忆是用户自己说的短句，关键词就够命中。真到几百条再考虑。

## 知识库

把 `.md` / `.txt` / `.markdown` / `.log` 丢进 `<数据目录>/knowledge/`，然后发 `/ai 知识 重建`。

- 目录：`data/bots/<机器人id>/plugins/ai-native/knowledge/`，`/ai 知识` 会直接打印绝对路径。
- 单文件上限 512KB，超了跳过并在日志里说明（别把整个访问日志丢进去）。
- 切块：先按空行分段，攒到 400 字左右一块；超长段落硬切并留 60 字重叠，避免答案正好被切断。
- 检索：BM25（`k1=1.2` / `b=0.75`，Lucene 默认值），中文用和记忆同一套「双字 + 单字」分词。
- **命中门槛看覆盖率，不看分数**：一段资料至少覆盖查询权重的 25% 才算命中。BM25 分数没有固定量纲，写死阈值换个语料就失灵；而「今天股市怎么样」里的「怎么」恰好出现在「魂环怎么升」里，光看分数不为零就会误命中。
- 每轮最多带 `knowledgeTop` 段（默认 3），以【参考资料】形式进提示词并标明来源文件名。

为什么不引向量库：embedding 要额外的 Key、额外的请求、额外的钱，还得管一个向量库进程。群机器人回答的多半是「魂环怎么升」「指令有哪些」这种词面能对上的问题，BM25 在小语料上并不差多少，成本为零。等文档上千篇、或者用户爱用同义改写提问，再上 embedding——检索层是可替换的，不会推翻现在的设计。

## 数据存哪

| 内容 | 位置 |
|---|---|
| 配置（含 API Key） | `config/bots/<机器人id>/plugins/ai-native.json` |
| 长期事实 | `data/bots/<机器人id>/plugins/ai-native.json`（`facts:<chatId>`） |
| 对话列表 | 同上（`convs:<chatId>`） |
| 摘要 | 同上（`summary:<chatId>#<convId>`） |
| 知识库文档 | `data/bots/<机器人id>/plugins/ai-native/knowledge/`（你自己放进去的原文） |
| 短期上下文 | 内存（`ctx.state`），重启即丢 |
| 日志 | `logs/bots/<机器人id>/plugins/ai-native.log` |

> ⚠️ API Key 明文存在本机配置文件里（和框架其他配置一致）。别把 `config/` 提交到公开仓库；面板默认只监听 127.0.0.1，别对外暴露。

## 说明

- 不引任何第三方依赖，`fetch` 是 Node 自带的。
- 语音消息直接用官方 ASR 结果（`msg.voices[].asrText`），不用自己识别。
- 图片默认只标注「[图片×N]」；开了 `vision` 会下载转 base64（>5MB 或下载失败回退 URL）。
- 主服务商失败（限流/超时/欠费）会按列表顺序自动试下一个；`fallback: false` 可关掉。
- 长任务不会超过 5 分钟被动回复窗口；超时会由框架自动降级为主动消息。
