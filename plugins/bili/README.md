# 刷 B 站（bili）

给机器人一双**能看 B 站的眼睛**：别人发链接时它能点进去看标题、简介、字幕和热评；你说「刷点 B站」它会换一批热门给你聊。

标准 MCP server，stdio，**零依赖**（只要 Node ≥ 20），0.4 有 10 个工具。
除了看视频，还能把一条视频分享成官方图文卡片、抽一帧画面存成本地图（要本机有 ffmpeg），
以及**可选地**在定时刷到好视频时主动推给主人 / 群。

> 这不是 `dsh-bili-scroll` 那种「每天替你刷一轮、写日报、发评论」的插件。
> 0.4 的定时刷默认关，每一项推送 / 写动作也都各有独立开关、默认全关，
> 写动作还额外默认「试运行」。装了扩展 ≠ 同意被推送，更 ≠ 同意拿你的账号留言。
> **写动作没有注册成 MCP 工具**，只有定时刷内部会跑：群里任何人的一句话、
> 视频标题或评论里的注入文本，都找不到能对外说话的工具。

## 工具

| 工具 | 什么时候用 | 入参 |
|---|---|---|
| `hot` | 「刷点 B站」「有什么好看的」 | `limit` 1–8、`fresh` |
| `weekly` | 「这周有什么必看」 | `number`（期数，不填最新）、`limit` |
| `search` | 「有没有 xx 的视频」 | `keyword`、`order`（play/pubdate/dm）、`limit`、`minPlay` |
| `video` | 有人发了链接 / BV 号 / 番剧 ep、ss | `link`、`comments`、`subtitle`、`danmaku` |
| `up` | 提到某个 UP 主 | `mid` 或 `name`、`limit` |
| `feed` | 「刚刷到什么」（定时刷开着时） | `limit` |
| `card` | 「分享这个视频」「发成卡片」 | `link` |
| `shot` | 「看看画面」「截一张图」 | `link`、`at`（秒） |
| `push` | 「把刚刷到的推给我」/ 验证推送链路 | `index`（第几条，默认 1） |
| `push_state` | 「推送开了吗」「怎么不推了」 | 无 |

模型看到的工具名是 `mcp__bili__hot`、`mcp__bili__video` 这样。
`feed` / `card` / `shot` 是 0.3 加的（`feed` 只读本地缓存、不打 B 站接口）；`push` / `push_state` 是 0.4 加的。

`video` 的输出长这样（约 950 字节）：

```
《每 天 亿 遍 🔥 防 止 早 恋！》
UP：兔总裁s ｜ 播放 195.4万 ｜ 点赞 5.8万 ｜ 弹幕 868 ｜ 评论 1903 ｜ 1:13 ｜ 1天前
https://www.bilibili.com/video/BV1ZAWM61Evb
简介：……
字幕：没登录看不到 AI 字幕（只有标题、简介和热评）
弹幕抽样：0:01 谁又惹她高兴了? / 0:31 ？ / 0:46 越看越人机
热评：
 - 下盘蟹：冷白皮特效太多了吧！[笑哭]（112 赞）
```

## 面板页面（0.5 起：扩展自带页面）

装好后「表达 → 刷 B 站」会多一页，**这一页是扩展自己写的 HTML**（`ui/index.html`），
面板用 iframe 装进来。页面里能做的事已经和 aurabot 的 B 站页对齐：

- **登录**：填 SESSDATA / bili_jct（secret，只存宿主 secrets，不回显明文），或**扫码登录**
  （B 站官方 `qrcode/generate` 接口 + 本地生成二维码，不起浏览器；装了共享依赖里的
  `qrcode` 就用它出码，没装则用内置编码器兜底）
- **排版**：对齐 aurabot 那页——「刷 B 站（登录）→ 怎么刷 → 评论、回复和分享 → 看画面 → 截图库 → ta 刷过什么 → 发弹幕 → 热门」
- **开关**：定时刷、主动推送、写动作、截图，30 项里常用项直接铺在页面上；**开关拨一下就存**，数字和文本点右上角「保存」
- **按钮**：刷新热门 / 现在刷一轮 / 检查登录 / 装 ffmpeg —— **全部在宿主进程里直接执行**，点了就出结果，没有队列、没有轮询
- **热门**：封面墙，和以前一样点开就能看
- **截图库**：刷一轮时顺手抽的帧（设置里「刷一轮时顺手截几张」，默认 0 = 不截），缩略图墙点开看大图；
  存在扩展自己的 `shots/` 下，构建脚本已跳过这个目录
- **ta 刷过什么**：今天刷了几轮 / 截了几张 / 评论几条 / 弹幕几条，跨天自动清零；
  打开页面会自动查一次登录态，不用先点「检查登录」

**动作怎么跑**：清单里 `ui.runtime: "inprocess"` + `ui.entry: "ui/main.mjs"`，宿主
`import()` 这个模块、调它导出的 `createActions()`，拿到一组函数直接绑到按钮上。
**没有任何 IPC**：`点击 → 普通函数调用 → 返回值回页面`。

只有宿主不认识 `ui.runtime` 的老版本才会退回队列（扩展仍保留 2 秒轮询兜底）。

**设置怎么生效**：面板保存后，宿主把值写进 `<数据目录>/extensions/<id>/config.json`
和 `secrets/<id>.config.json`；扩展在**每次工具调用 / 每一轮定时刷之前**直接读这两个
文件（`lib/live-config.mjs`），所以改完设置下一次动作就是新值——**不需要重启子进程**，
也不依赖宿主的 `mcpManager.restart()`（它对受管块里的静态条目基本无效）。
定时刷的频率、总开关改了，`feed.syncTimer()` 会当场重排定时器。

**宿主怎么支持**：清单 `ui.page` 指向 HTML 入口，面板 `/ext-pages?id=<扩展>&file=<路径>`
把文件按 MIME 发出去，前端用 iframe 渲染。路径卡在扩展目录内；`/ext-pages` **不过**面板
API 的 fence——iframe 导航请求带不了自定义头，过栅栏会被 403。

**声明式 `ui.view` 仍然保留**（0.2–0.4 的卡片墙）：不想写页面的扩展继续用它，
数据还是 `ui-data.json`，宿主只读数据、不执行扩展代码。

**默认什么时候刷新数据**（两个时机，都不额外发请求）：

1. 进程启动后 1.2 秒，拉一次热门写下来；
2. 每次模型调用 `hot` 工具之后，把刚拉到的那一份写下来。

0.3 加了**可选**定时刷（默认关）：设了「定时刷间隔 ≥15 分钟」后，每轮拉一次热门，
喂给 `hot` 的缓存和面板，`feed` 工具也能读到最近那批。0.2 之所以刻意不做定时刷新，
是因为 MCP server 是长驻进程，装了就一直打 B 站接口，412 迟早的事——所以现在仍然
默认关，开了还叠三道闸：活跃时段、刷新前探一次宿主 `/v1/state`、撞过 412 的退避期内跳过。

0.4 起，定时刷还会按开关投素材 / 抽帧 / 跑写动作，见下面「主动推送与开关」那节；
**开关一个都不开时，行为和 0.3 完全一样**（只预热缓存和面板）。

**改字段要两边一起改**：`ui.view.fields` 的 `key` 必须和 `lib/ui-data.mjs` 的 `rowsOf()`
输出对得上，否则面板那一列永远是空的（`test/ui-data.mjs` 有一条断言钉住这件事）。

**一级菜单可以自己选**：`ui.nav.group` 支持 `home` / `self` / `express` / `group` / `power` / `mods` / `system`，
也认中文（概览 / 人设 / 表达 / 群聊 / 能力 / 扩展 / 系统）。现在挂在「表达」下——
她「说什么」的来源，比埋在「扩展」里好找。想换就改这个字段。

## 装

**面板装**：扩展 → 市场 → 「刷 B 站」→ 安装 → 在权限页把 `ext_bili` 组调好。

**手放**（开发时更快）：

```
<数据目录>/extensions/bili/     # Windows: %USERPROFILE%\.dsh\dsh-roost\extensions\bili\
  plugin.json  server.mjs  lib/  README.md
```

放好之后重启 Roost（或让面板重载），工具会在下一轮出现。装完想确认通没通，直接问机器人「刷点B站」。

**注意**：`plugin.json` 里的 `command` 只是给宿主 launcher 读的，真正被 spawn 的是 `node ./server.mjs`，`cwd` 就是这个扩展目录。

## 登录态（可选，0.3 起推荐用面板）

匿名也能用（热门、搜索、视频信息、热评、弹幕都拿得到），但 **AI 字幕和高清流要登录**。

**首选**：面板「表达 → 刷 B 站 → 设置」里把整段 Cookie 填进「B 站 Cookie」。
它标了 `secret`，只存宿主的 `secrets/<id>.config.json`（0600），不进 `config.json`、
也不会下发到面板；扩展进程通过 `ROOST_EXT_SECRET_COOKIE` 拿到。

**兼容 0.2**：也可以在扩展目录放一行 `cookie.txt`（`SESSDATA=...; bili_jct=...`），
按文件 mtime 热读、改完不用重启。**面板里的 secret 优先**，两边都填时以面板为准。

- 0.4 起，定时刷的写动作（评论 / 点赞 / 弹幕）也会用它，但**默认试运行且默认关**；评论和弹幕的文案由她自己写，没有模板；
- Cookie 等于账号密码：别提交到仓库、别贴进聊天记录、别放进截图；
- 不想要了清空面板那栏 / 删掉文件即可。

## 发卡片 / 发截图：扩展不自己发

`card` 返回一行 `<<card: 标题|描述|https://链接|https://封面>>`，
`shot` 返回一张本地图的绝对路径加一行 `<<image-alone: 路径>>`。
**这两行要由模型原样写进回复**，宿主出站动作层才会发出去。

为什么不直接调 `POST /v1/send`：MCP 工具调用只带 `arguments`，扩展根本不知道
「当前是哪个会话」，而 `/v1/send` 必须有 `target`。另一条 `/v1/proactive` 触发的是
宿主自己的主动搭话，内容不受扩展控制，拿它推视频等于让她莫名其妙冒一句。
所以模型在**有人在场的那一轮**里，要按语境自己写标记发出去。

0.4 补了另一条路：定时刷可以调宿主 `POST /v1/proactive/submit` 投一份**素材**，
由宿主排队、过门闸、让模型组织语言后主动发出。扩展依旧不知道「当前会话」，
也不写成品文案——只是把「发给谁」换成宿主按配置解析的 `owner` / `group:群号`。

卡片四项必填、链接和封面必须是 https（B 站 CDN 天然满足），标题 ≤50 字、描述 ≤200 字；
工具里已经把竖线、尖括号、长度都收拾好了，别手改那行标记。一轮最多写一张。
**本地截图不能塞进卡片封面**（官方只收 https）——它走 `<<image-alone:>>` 发图。

`shot` 需要本机 ffmpeg，从 DASH / 渐进式流里 seek 抽一帧，不下载整片。
没 ffmpeg / 没登录拿不到流 / CDN 不支持 seek 时，工具会直接说清缺什么，不影响其它工具。
截图默认存**系统临时目录**下的 `dsh-bili-shots/`，别改成扩展自己的目录：市场索引按整个目录算 sha256，
运行时多一张 jpg 会让 `build-index --check` 变脏。

**ffmpeg 装在哪**：不在扩展目录，在**宿主的共享目录** `<DSH 数据目录>/deps/`。
面板「刷 B 站」页顶部没装时会出一个「装 ffmpeg」按钮，点它由宿主装一次（`@ffmpeg-installer/ffmpeg`，
约 62 MB，`--ignore-scripts`），装好后**所有扩展和框架功能一起用**；
扩展只通过 `ROOST_DEPS_DIR` 找它，升级扩展、卸载扩展都不会把它删掉。
想要指定别的版本时，才在设置里填「ffmpeg 路径」覆盖。

## 为什么没有「评论 / 弹幕 / 点赞 / 分区榜」

**写接口一个都没注册**，不是「注册了但提示模型别用」。原因：这个扩展在**群聊**里被调用，而它读的又是 B 站用户写的外部文本（标题、简介、评论、弹幕）——天生是提示注入的温床。把「能发东西的工具」从注册表里拿掉，注入写得再漂亮也无从调用；这比在提示词里写一百遍「不要发评论」可靠。要发评论请到框架插件侧做。

**分区排行榜拿掉了**：`ranking/v2?rid=N` 现在返回的是 2025-03-31 那一周的冻结快照（rid 4 / 36 / 188 实测同一天），拿它当「现在游戏区第一」会当场露馅。换成官方的「每周必看」（`weekly`），日期是真实的。

## 几个刻意的工程取舍

- **4 KB 预算**：宿主会在 4096 字节处硬截断工具输出（`src/ext-usage.js`），所以 `lib/format.mjs` 自己在 3600 字节处收口，字幕只给 420 字节、热评只给 4 条。中文一个字 3 字节，看着短其实刚好。
- **每次换一批**：`hot` 拉一份 20 条的池子，调用一次往后挪 6 条。同一批视频连推三次，谁都知道你没真刷。
- **请求节流 + 退避**：两次请求之间随机停 0.5–0.9 秒；命中 `412` / `-352` 就进程内停 10 分钟，不再撞墙。旁路接口（字幕 / 评论 / 弹幕 / 空间）不触发全局暂停 —— 一个可选字段拿不到，不该把整轮废掉。
- **搜索空结果重试一次**：B 站连着几个请求时会回 `code 0` + 空 `result`（软限流），等 800 ms 再问一次通常就有了。
- **弹幕均匀抽样**：从全片按步长取 8 条再按时间排序，比只看开头更能看出「这一片在聊什么」。
- **参数校验自己来**：MCP 客户端不会拒未知字段，模型把 `keyword` 写成 `keywrod` 会静默查空。这里直接报「不认识的参数：keywrod」。
- **`/v1/state` 里没有清醒时段**：它只给 mood / bindings / lastBucket。定时刷的「半夜别刷」只能在扩展自己按 `feedActiveHours` 判；宿主的 `shouldFire()` 那份判定扩展看不到，硬猜会照刷。刷新前仍会探一次 `/v1/state`，宿主没在线就不白打 B 站。
- **卡片字段在工具里就裁好**：宿主那边验不过只会记一条日志、卡片静默不发；与其让模型莫名其妙少一张卡片，不如在源头把长度、https、分隔符都收拾干净，缺封面就当场说原因。

## 调试

```bash
node server.mjs --list                              # 列出工具
node server.mjs --call hot '{"limit":3}'            # 直接调一个工具（不经宿主）
node server.mjs --call card '{"link":"BV1xx..."}'   # 拼一张卡片（不联网以外的接口）
node server.mjs --call feed '{}'                    # 看定时刷缓存
node test/card.mjs && node test/feed.mjs            # 0.3 的离线用例
node test/shots.mjs && node test/tools03.mjs        # 抽帧 / 工具层（假 ffmpeg，不联网）
node test/smoke.mjs                                 # 离线协议冒烟：握手 / 工具表 / 参数校验
node test/live.mjs                                  # 真打 B 站接口（手动用，会发网络请求）
```

`--call` 的日志走 stderr，正文走 stdout —— 手动跑时两者都会显示，接进宿主时只有 stdout 是协议通道。

## 可调设置

装好后在「扩展 → 已装扩展」点 `bili` 那行的**设置**，改完保存、重启 DSH 生效（面板会试一次自动重连）。

| 设置 | 默认 | 作用 |
|---|---|---|
| 默认条数 | 6 | 模型没指定 `limit` 时用。群聊里建议 3–5，长了刷屏 |
| 热门池大小 | 20 | 一次拉多少条备选；每次调用换一批，池子越大越不容易复读 |
| 热评条数 | 5 | `video` 工具带几条热评 |
| 默认带弹幕 | 关 | 打开后 `video` 默认附带弹幕抽样（多一次请求，慢一点） |
| B 站 Cookie | 空 | **secret**。填了才能看 AI 字幕 / 拿高清流；不进 `config.json` |
| 定时刷间隔（分钟） | **0 = 关** | 填 15 以上才启动；开关全关时只预热缓存和面板 |
| 允许定时刷的时段 | 空 = 全天 | 如 `9-23`，也支持跨午夜 `22-6` |
| ffmpeg 路径 | 空 = 用宿主共享目录 | `shot` 抽帧要用；一般不用填，面板点「装 ffmpeg」即可 |
| 截图宽度 | 512 | 高度按比例缩放 |
| 最多留几张截图 | 12 | 超了删最旧的，只删本扩展按 `BV号-秒数.jpg` 命名的那些 |
| 截图目录 | 扩展自己的 `shots/` | 固定不可改：面板只从这里取图，构建脚本也已跳过 |

### 0.4 主动推送与写动作（每项一个开关，默认全关）

| 开关 | 默认 | 管什么 |
|---|---|---|
| 刷到好视频 → 私聊推给主人 | 关 | 投素材到宿主，由模型写措辞、宿主过门闸 |
| 刷到好视频 → 推到群 / 推送群号 | 关 / 空 | 群号只认数字，宿主会真算 `group_push` 授权 |
| 推群前先问主人 | 关 | 攒待批，私聊回「发 1」或面板点「发」才真发 |
| 素材里带封面地址 / 推送门槛 / 每天最多推几条 / 每轮最多挑几条 | 关 / 10 万 / 20 / 1 | 同一个 BV 号当天不重复推 |
| 定时刷时自动抽帧存库 | 关 | 只存本地，**不主动发图**（主动轮次会抹平 `<<...>>` 标记） |
| 定时刷时自己评论 / 发弹幕 | 关 | **没有模板**：话是她看过简介、字幕、热评之后自己写的（独立会话），开关只决定允不允许这条出口 |
| 回别人回她的评论 | 跟评论开关 | 刷完先查一遍「有人回了你」（已回过的记在 `replied.json`，不会回十遍），她在同一轮里决定回不回 |
| 主人的 B 站昵称 | 空 | 填了就在自动评论 / 回复末尾写 `@昵称`（B 站的 @ 只是文本，不会真发提醒） |
| 定时刷时顺手点赞 | 关 | 点赞不需要文案，所以留在扩展里直接做 |
| 推送时顺手发张截图 | 0（从不） | 百分比。命中就截一张，把路径写进推送素材，她愿不愿意发由她决定 |
| **写操作试运行** | **开** | 关掉才会真的往 B 站写；撞到风控码自动暂停当天 |
| 每天最多写几次 | 10 | 评论 / 点赞 / 弹幕合计，试运行也计入 |

`push` 工具可以手动补推最近一条，`push_state` 能看开关、今日额度和上一轮结果
（用户问「你怎么不推了」先调它，别猜）。

**需要重新授权**：0.4 的清单声明了 `proactive:write`（敏感 scope）。升级后宿主要
在扩展页确认一次，否则 `/v1/proactive/submit` 会回 403「缺少 scope」，`push_state`
里会看到「通道不可用」。

模型显式传了参数时以模型为准，设置只决定默认值。上限仍由工具 schema 约束（条数最多 8）。
`secret` 那栏改完保存即可，其它设置改完重启 DSH 生效（stdio 扩展是宿主拉起的子进程）。

## 已知边界

- 不支持直播、付费 / DRM 内容、番剧的播放地址；
- `shot` 能抽帧但不下载整片，也不自己发图（返回路径给模型写 `<<image-alone:>>`）；没 ffmpeg 或没登录拿不到流时会直说；
- 弹幕走的是旧版 `list.so`，B 站哪天关掉它就只剩「无弹幕」；
- UP 主的「最近投稿」接口反爬很硬，偶尔只回资料、投稿为空（会如实写「拿不到」）；
- 未登录时字幕基本为空（B 站的 AI 字幕要登录）；
- 面板那页只有热门，搜索/每周必看的结果不进面板（那两条要参数，面板上没有输入框）。
